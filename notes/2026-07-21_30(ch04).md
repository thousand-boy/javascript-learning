### 4-1〜4-3｜イベントの仕組み／ローディング画面（load・classList.add）

**何をしたか**
- **4-1 イベントとは？（p.092〜093）**：イベントとは **ユーザーの操作に応じて動作を起こすきっかけ**。クリック、キーボード操作、スクロール、ページ読み込みなど様々なタイミングで発生し、JavaScript には **あらかじめ用意した処理をイベント発生時に呼び出す仕組み** が備わっています。流れは4段階：**①処理の登録（「何が」「どうなったら」「どうなるか」を指定。この時点では実行されず"予約"されている） → ②ブラウザーが監視 → ③発生を検知して通知 → ④登録した処理を呼び出す**。
- **4-1（続き）よく使うイベント20種を一覧で確認**：`load` `submit` `reset` `resize` `scroll` `copy` `paste` `keydown` `keyup` `click` `dbclick`（※表記注意・後述） `mousedown` `mouseup` `mouseover` `mouseout` `select` `focus` `blur` `input` `change`（詳細は用語表）。
- **4-2 ローディング中の画面を作ろう（p.094〜096／サンプル `chapter4/02-demo`）**：読み込みに時間がかかるページで、表示までの時間を埋めるローディング画面。動きは **①スピナー表示 → ②画像の読み込み → ③ローディング画面が少しずつ消える → ④画像が表示**。完成コードは `index.html`／`js/script.js`／`css/style.css`／`images/`。**POINT：ブラウザー間の表示を統一するリセットCSS `ress.css`**（`https://unpkg.com/ress/dist/ress.min.css`）を読み込んでいます。
- **4-3 CSSのクラスを加えよう（p.097〜101）｜作り方の流れ**：**①ローディング画面とコンテンツを HTML＋CSS で作成 → ②JavaScript で「ローディングが終わったらローディング画面を消す」指示を書く**。ローディング画面の `<div>` に **`loading` という ID** を割り振り、`position` プロパティでコンテンツと重ねます。
- **4-3（続き）`inset: 0;` の意味**：`top: 0; right: 0; bottom: 0; left: 0;` をまとめた指定。**`position: fixed;` と組み合わせることで要素を画面いっぱいに広げられる**ので、覚えておくとよい書き方。
- **4-3（続き）イベントの用意**：**イベントのターゲットは画面なので `window` が一番はじめ** にきます。**画像・音声・動画などすべてのリソースの読み込み完了** には **`load`** を使用。処理は短いので無名関数で書きます。
- **4-3（続き）クラスの付与**：CSS に **要素の不透明度を0にして隠すクラス `.loaded`**（`opacity: 0;` ＋ `visibility: hidden;`）を用意し、**`classList.add()`** で付与。**クラス名はシングルクォーテーションで囲む**。非表示にしたい `#loading` を定数に入れ、`loading.classList.add('loaded')` で完成。
- **4-3（続き）削除と複数指定（p.101）**：削除は **`classList.remove()`**。**カンマ区切りで一度に複数のクラスを追加・削除できる**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| イベント／`addEventListener()` | 操作や状態変化をきっかけに処理を呼ぶ仕組み／`要素.addEventListener('イベント名', 処理)` で登録 |
| 無名関数 | 関数名を付けない関数。`() => { … }` の形でイベント処理に直接書ける（P.080参照） |
| `load` | スタイルシートや画像など、すべてのリソースの読み込みが完了したとき |
| `submit` / `reset` | フォームが送信されるとき／リセットされるとき |
| `resize` / `scroll` | 画面のサイズが変わったとき／スクロールされたとき |
| `copy` / `paste` | コピーされたとき／ペーストされたとき |
| `keydown` / `keyup` | キーが押されたとき／離されたとき |
| `click` / `dbclick`（※教材表記） | クリックされたとき／ダブルクリックされたとき。**正しいDOMイベント名は `dblclick`** |
| `mousedown` / `mouseup` | マウスのボタンが押されたとき／離されたとき |
| `mouseover` / `mouseout` | マウスカーソルが重なったとき／離れたとき |
| `select` / `focus` / `blur` | テキストを選択したとき／要素にフォーカスされたとき／フォーカスがはずれたとき |
| `input` / `change` | 入力されたとき／変化があったとき |
| リセットCSS（`ress.css`） | ブラウザー間の初期スタイル差をそろえるCSS |
| `inset: 0;` | 上下左右すべて0の指定。`position: fixed;` と併用で画面いっぱいに広がる |
| `z-index` / `place-items: center` | 重なり順を指定／Grid で子要素を縦横中央に配置 |
| `classList.add()` / `classList.remove()` | 指定した要素にクラスを追加／削除する |
| `visibility: hidden` | 要素を非表示にする。`opacity: 0` と併用 |
| `defer` | `<script>` 属性。HTML解析後にJSを実行するので要素取得に失敗しにくい |

```js
const loading = document.querySelector('#loading');   // 非表示にしたい要素を定数に

  loading.classList.add('loaded');        // 「loading」に「loaded」クラスを追加
});
```

```js
// ===== 4-3 削除と複数指定（p.101） =====

```

**できるようになったこと**：イベントの仕組みを「登録→監視→検知→呼び出し」の4段階で説明できるように。`position: fixed` ＋ `inset: 0` ＋ `z-index` ＋ `place-items: center` でコンテンツに重なる全画面ローディング画面を作り、`window` の `load` で全リソース読み込み完了を検知して `classList.add('loaded')` で非表示化、`transition` でふわっと消す実装。

**つまずき・気づき**
- **教材の表 `dbclick` は要注意**。MDN で定義されている正しいDOMイベント名は **`dblclick`**（`b` と `c` の間に `l`）。誤って書いてもエラーにならず「反応しないだけ」なので気づきにくい。※教材の誤植か写真の判読ミスかは断定できず（要確認）。
- `load` は **HTMLの解析完了ではなく、画像などすべてのリソースが読み終わったタイミング**。だからローディング画面を消すきっかけとして使える。
- `.loaded` に `opacity: 0` **だけ** だと見えないまま画面上に残り、下のコンテンツがクリックできなくなる。`visibility: hidden` を併記するのがセット。逆に `display: none` だと `transition` が効かない。
- **「CSS にクラスを用意しておき、JS はクラスを付け外しするだけ」** という役割分担。見た目の定義がCSS側に集約されるので後から調整しやすく、この考え方が 4-5 の `toggle` にも続きます。

### 4-4〜4-6｜ダークモード切替（click・classList.toggle・textContent＋if/else）

**何をしたか**
- **4-4（p.102〜103／サンプル `chapter4/04-demo`）**：**ダークモードとは画面の背景を黒基調にしたデザイン**。CSSのカスタムプロパティやメディア特性で **OSの設定を判定する方法もある** が、ここでは **ボタンをクリックして切り替えるタイプ** を実装。HTML は `<button id="btn">` ＋ `<h1>` ＋ 説明の `<p>` のみ。
- **4-5 CSSのクラスを切り替えよう（p.104〜106）**：ボタンの処理を **`click` イベント** で指定。**見た目を変更するなら、処理内容に「CSSのクラスの有無を変更する」指定を入れるとよい**。CSS に **`dark-theme`**（背景 `#000`／文字色 `#ddd`）を用意しておき、**この段階ではHTML内のどの要素にも加えていません**。
- **4-5（続き）`classList.toggle()`**：クリックのたびにつけ外ししたいので `add`／`remove` ではなく **`toggle`** を使用。**指定した要素にクラス名が付いていなければ追加、付いていれば削除**。**body要素は `document.body` で取得** でき、`<body class="dark-theme">` ⇔ `<body class="">` が往復します。
- **4-5（続き）残った課題**：スタイルは切り替わったが、**ダークモードになってもボタンのテキストが「ダークモードにする」のまま**。
- **4-6 ボタンのテキストを変更しよう（p.108〜109）**：**まず日本語で整理** するのがコツ。「もし今『ダークモードにする』なら『ライトモードにする』に変更、そうでないなら戻す」。要素のテキストは **`textContent`** で挿入でき、条件には **`btn.textContent === 'ダークモードにする'`** を使って現在の表示を評価します。
- **4-6（続き）コメントアウトで整理**：**条件を付けるときやコードが長くなりそうなときは、一旦日本語で考え、コメントアウトを使いながら整理してコードを書いていく** とよい。実際に日本語の擬似コードを `//` として残したまま完成させました。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| ダークモード | 画面の背景を黒基調にしたデザイン |
| `click` | クリックされたときに発生するイベント |
| `classList.toggle()` | クラスが無ければ追加、有れば削除。オン／オフの往復切替に最適 |
| `document.body` | `<body>` 要素を取得する書き方 |
| `textContent` | 要素のテキストを取得・挿入できるプロパティ |
| `===`（厳密等価） | 値と型が一致するかを評価する比較演算子 |
| `if / else` 文 | 条件が成立するとき／しないときで処理を分ける（P.086「3-11」で学習） |
| コメントアウト（`//`） | 実行されない注釈。日本語で処理を整理する下書きに使える |
| `transition: .5s` / `cursor: pointer` | 変化を滑らかに／クリックできることを示すカーソル |

**学んだ主な構文**

```css
/* ===== 4-4／4-5 css/style.css ===== */
body { padding: 2rem; transition: .5s; }      /* 切り替えを滑らかに */
.dark-theme {                                  /* ← ダークモード用に用意したクラス */
    background: #000;
    color: #ddd;
}
#btn {
    background: #0bd; padding: 1rem; margin-bottom: 2rem;
    font-size: 1rem; color: #fff; border-radius: 8px;
    border: 0; cursor: pointer;
}
```

```js
// ===== 4-5 toggle の書き方（p.105） =====
要素.classList.toggle('クラス名');
// <body class="dark-theme">  ⇔  <body class="">
```

```js
// ===== 4-6 完成形（p.109／js/script.js） =====
const btn = document.querySelector('#btn');

btn.addEventListener('click', () => {
  document.body.classList.toggle('dark-theme');   // 追加と削除を交互に

  // もしボタンのテキストが「ダークモードにする」になっているなら
  if (btn.textContent === 'ダークモードにする') {
    btn.textContent = 'ライトモードにする';
  // そうでないなら（「ライトモードにする」と表示されているなら）
  } else {
    btn.textContent = 'ダークモードにする';
  }
});
```

**できるようになったこと**：`click` ＋ `classList.toggle()` で `document.body` に自作クラスを付け外しし、ライト／ダークを切り替える実装。`btn.textContent === …` の厳密等価で現在の状態を評価し、`if / else` と `textContent` の代入でボタンのラベルも往復させるところまで。「複雑になりそうならまず日本語で書き、コメントとして残しながらコード化する」進め方も習得。

**つまずき・気づき**
- **`add`／`remove` と `toggle` の使い分け**が明確になった。一方向の状態変化（ローディング終了＝二度と戻らない）は `add`、クリックごとに往復する状態は `toggle`。
- 見た目は `toggle` で切り替わっても **ボタンのラベルは自動では変わらない**。「状態」と「その状態を説明するUI表記」は別物で、どちらも明示的に更新する必要がある。
- **表示テキストを状態の判定材料にしている**（`btn.textContent === …`）のは入門としては分かりやすいが、**ラベルを1文字変えると条件が成立しなくなる**危うさがある。より堅牢にするなら `classList.contains('dark-theme')` や `toggle()` の戻り値で判定する手も。※教材本文にはない自分の考察。
- `transition: .5s` は **切り替わる要素（`body`）側** に書く。4-2 の `#loading { transition: all 1s; }` と同じ設計。
- **教材内の節番号表記のズレ**：p.102 の見出しは「4-4」でサンプルも `04-demo` だが、`index.html` の `<title>` は「**4-5.** …」となっている（4-7→「4-8.」も同様）。

### 4-7〜4-9｜文字数カウンター（keyup・length・比較演算子）

**何をしたか**
- **4-7（p.110〜111／サンプル `chapter4/07-demo`）**：テキストの入力フォームでは **入力できる文字数を制限しているものもある**。文字をカウントして表示し、**100文字より多くなると数字の色が変わる** ようにします。HTML は `<textarea id="text">` ＋ 注意書き ＋ `<p>現在 <span id="count">0</span> 文字</p>`。
- **4-8 lengthでカウントしよう（p.112〜115）**：**これまで通りイベントの指定 → 処理内容を書く** 順で記述。**文字数を表示したい箇所は `<span>` で囲み `count` という ID を割り振る**。指示に使う要素を定数（`text`／`count`）として用意し、「テキストエリアに入力されたら」には **`keyup`**（キーボードで入力したとき、正確にはキーから手が離れたとき）を使用。
- **4-8（続き）`length`**：**数えたい文字列のあとに `.length` をつなげるだけでOK**。length は「長さ」の意味で、文字列の長さ＝文字数をカウントします。コンソールで `'文字列'.length;` → `3` を確認。**すでに入力された値は `要素.value` で取得できる** ので `text.value.length` を `count.textContent` に代入すれば、入力するたびに数字が増えていきます。`length` は **要素の数を数えるときにも使える** ので慣れておくとよい。
- **4-8（続き）lengthだけで文字数を取得できない文字もある（p.115）**：**絵文字や一部の漢字では1文字でも2文字とカウントする**。脚注では **Unicode で1文字を2つの文字コードで表す文字**（通常「1文字＝2バイト」のところ一部は「1文字＝4バイト」）を **サロゲートペア** と呼ぶと説明。回避策として **スプレッド演算子** `[...'😄'].length` → `1`。
- **4-9 文字数によって表示を変えよう（p.116〜118）**：CSS に **`alert` クラス**（`color: #f66;`）を用意し、100文字を超えたら付与します。**「100文字を超えると」という条件式はひとまず置いておき、書けるところだけ書く** のがコツ。条件には **算数でもおなじみの不等号** を使い、**`>` は左側が右側よりも大きいかを評価**。**このように左右を比較する記号を「比較演算子」と言う**ので、`text.value.length > 100` と記述できます。**101文字目から数字部分の文字色が変わる** 動作を確認。
- **4-9（続き）比較演算子の種類**：`===` もこれまで使ってきた比較演算子の1つ。**`>=` や `<=` は不等号の「≧」「≦」と同じ意味**。**POINT：記号の順序をひっくり返して `=>` や `=<` と書くと演算子として認識されなくなる**ので注意。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `<textarea>` / `<span id="count">` | 複数行の入力欄／文字数を差し込む箇所 |
| `keyup` | キーが離されたときに発生。キーボード入力の検知に使う |
| `要素.value` | 入力フォームに **すでに入力されている値** を取得する |
| `.length` | 文字列の長さ（文字数）を返す。要素の数を数えるときにも使える |
| サロゲートペア | Unicodeで1文字を2つの文字コードで表す文字。`length` では2とカウントされる |
| スプレッド演算子（`[...文字列]`） | 文字列を1文字ずつに展開する書き方 |
| 比較演算子 | 左右を比較する記号の総称 |
| `.alert` | 100文字超で付与する自作クラス（`color: #f66`） |
| `max-width: 100%` | 固定幅を基本にしつつ、画面が狭いときだけ縮めるレスポンシブの定番 |

**比較演算子の一覧（p.118）**

| 演算子 | 意味 | 演算子 | 意味 |
|---|---|---|---|
| `A === B` | AとBが等しいか | `A >= B` | AがB以上か |
| `A > B` | AがBを超えるか | `A <= B` | AがB以下か |
| `A < B` | AがB未満か | `A !== B` | AとBが等しくないか |

**学んだ主な構文**

```js
// ===== 4-9 完成形（p.118／js/script.js） =====
const text = document.querySelector('#text');    // テキストエリア
const count = document.querySelector('#count');  // 文字数の表示先

text.addEventListener('keyup', () => {
  count.textContent = text.value.length;

  // 100文字を超えるなら
  if (text.value.length > 100) {
    count.classList.add('alert');       // alert クラスを加える
    // そうでないなら（100文字以下なら）
  } else {
    count.classList.remove('alert');    // alert クラスをはずす
  }
});
```

**できるようになったこと**：`keyup` で入力を検知し、`要素.value` ＋ `.length` で文字数を数えて `textContent` に反映するリアルタイムカウンター。比較演算子 `>` で条件式を書き、`classList.add`／`remove` で警告色を付け外しする処理。比較演算子6種と `=>` `=<` の落とし穴。`length` がサロゲートペアを2と数えることとスプレッド演算子による回避策。

**つまずき・気づき**
- **`keyup` はマウス操作のペーストを拾えない**。MDN によれば <cite index="27-1">keyup はキーが離されたときに発火する</cite>のに対し、<cite index="30-1">input イベントは `<input>`／`<select>`／`<textarea>` の値がユーザー操作の直接の結果として変化したときに発火する</cite>。つまり右クリック→貼り付け、ドラッグ＆ドロップ、音声入力ではカウンターが更新されない。教材自身が p.093 で `input` を紹介しているので、実務なら **`input` の方が適切**。
- **日本語入力（IME）との相性**にも注意。MDN は <cite index="27-1">Firefox 65 以降、keydown と keyup が IME 変換中にも発火する</cite>と記し、除外には `event.isComposing` を見るよう案内している。
- **スプレッド演算子は「完全な解決」ではない**。コードポイント単位なので、ZWJ結合の家族絵文字や結合文字では複数にカウントされる。人間が見た「1文字」で数えるなら、<cite index="16-1">2024年4月以降すべての最新ブラウザーで利用できる（Baseline Newly available）</cite>とMDNが記す `Intl.Segmenter`（`granularity: 'grapheme'`）が本筋。※教材の範囲外。
- **`.alert` に `toggle` を使わないのは正しい**。`toggle` は往復する操作向けで、今回は「文字数という値に従って毎回決め直す」ので `add`／`remove` を明示するほうが安全（`toggle` だとキー入力ごとに反転してしまう）。
- 表示上100文字を超えても **送信自体は止められない**。実際に制限するなら `maxlength` 属性やサーバー側の検証が別途必要。※教材本文にはない補足。

### 4-10〜4-12｜チェックで有効化（change・真偽値・disabled・論理否定「!」）

**何をしたか**
- **4-10（p.120〜121／サンプル `chapter4/10-demo`）**：「必須項目に入力したら」「規約に同意したら」など、**特定の条件を満たすとボタンが押せるようになるフォーム**。HTML は `<label><input id="check" type="checkbox">…</label>` と `<input id="btn" type="submit" value="送信する" disabled>` の2行だけ。
- **4-11 チェックでボタンを有効化しよう（p.122〜126）**：チェックボックスは **「チェックしているか」「していないか」の2状態** を切り替えられます。**ボタンには `disabled` 属性を付与して無効（押せない状態）** にしておき、CSS では **疑似クラス `:disabled`** で背景を薄いグレーに。
- **4-11（続き）`change` と `checked`**：チェックボックスの要素を **`isAgreed`**、ボタンを **`btn`** に格納。**変化があったときに発動させるには `change` イベント**。`console.log(isAgreed.checked)` にすると（**文字列ではないのでクォート不要**）、**チェックを入れたら `true`、外したら `false`** と表示されます。
- **4-11（続き）真偽値**：**`true` や `false` は真偽値（ブール値）と呼ばれる特別なデータの型**。これまで「条件に当てはまる／当てはまらない」と説明してきたものを、**当てはまる＝`true`（真）、当てはまらない＝`false`（偽）** と表現します。「はい／いいえ」で答えられる質問の返答がこれ。
- **4-11（続き）if文で有効化**：**`disabled` 属性は JavaScript でも `要素.disabled` で操作できる**。読み込み直後は `btn.disabled` が `true`＝無効化が効いている状態で、チェックが入ったら `false` にします。さらに **if 文の条件で使う `=== true` は省略できる** ので `if (isAgreed.checked)` と書いても同じ動作。
- **4-12 より効率のいい書き方を考えよう（p.127〜128）**：前節の書き方でも問題はないが、**プログラムは効率よく書いていくのも大事**。入出力を観察すると「`isAgreed.checked` が `true` なら `btn.disabled` は `false`」「`false` なら `true`」、つまり **チェックボックスとボタンの無効化の状態は常に逆**。そこで **逆を意味する記号 `!`**（4-9 の `!==` でも登場）を `isAgreed.checked` の前に付けて否定し、**1行に集約**。**慣れるまでは `if`／`else` で書いて問題ないが、少しずつより効率よく書く方法がないか考えてみるとよい**とのこと。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `type="checkbox"` | `<input>` をチェックボックスにする指定 |
| `disabled` 属性 / `:disabled` | 要素を無効化するHTML属性／無効状態だけに当たるCSS疑似クラス |
| `change` | 値に変化があったときに発生するイベント |
| `要素.checked` | チェックの有無を `true` / `false` で返す。文字列ではないのでクォート不要 |
| 真偽値（ブール値） | `true`（真）と `false`（偽）だけを取る特別なデータ型 |
| `要素.disabled` | JSから無効化を操作する。`true` で無効、`false` で有効 |
| `=== true` の省略 | 条件が真偽値そのものなら `if (x === true)` は `if (x)` と書ける |
| `!`（論理否定） | 真偽値を反転させる。`!true` → `false`、`!false` → `true` |

**学んだ主な構文**

```html
<!-- ===== 4-10／4-11 index.html（chapter4/10-demo） ===== -->
<label><input id="check" type="checkbox"> 利用規約に同意する</label>
<input id="btn" type="submit" value="送信する" disabled>   <!-- disabled で無効化 -->
```

```css
/* ===== 4-10／4-11 css/style.css ===== */
body { text-align: center; padding: 2rem; }
label { display: block; margin-bottom: 1rem; }
#btn { background: #0bd; padding: .75rem 1rem; border-radius: 8px; }
#btn:disabled { background: #ccc; }      /* 無効の状態では背景をグレーに */
```

```js
// ===== 4-11 if / else 版（p.125〜126／js/script.js） =====
const isAgreed = document.querySelector('#check');
const btn = document.querySelector('#btn');

isAgreed.addEventListener('change', () => {
  if (isAgreed.checked) {        // 「=== true」は省略できる
    btn.disabled = false;        // ボタンの無効化をなしにする
  } else {
    btn.disabled = true;         // ボタンを無効化する
  }
});
```

```js
// ===== 4-12 完成形：「!」で1行に（p.128／js/script.js） =====
isAgreed.addEventListener('change', () => {
  btn.disabled = !isAgreed.checked;   // 前に「!」を付けて逆の結果を代入
});
// checked が true なら false、false なら true が disabled に入る
```

**できるようになったこと**：`type="checkbox"` ＋ `disabled` ＋ `:disabled` で「押せないボタン」を用意し、`change` と `要素.checked` でチェック状態を取得、`要素.disabled` に代入して有効化する実装。真偽値というデータ型の理解と `=== true` の省略。さらに **チェック状態と無効化状態が常に逆** という法則を見抜き、`!` で1行にリファクタリングするところまで。

**つまずき・気づき**
- **`if / else` 4行 → `!` で1行** への圧縮がこの章で一番学びが大きかった。ポイントは短縮技を先に覚えたのではなく、**まず動くコードを書き、入出力を眺めて「常に逆になっている」法則を発見した** という順序。教材も「慣れるまでは if / else で問題ない」と明言している。
- **`isAgreed` という定数名が秀逸**。`check` ではなく「同意しているか」と真偽を問う名前なので、`if (isAgreed.checked)` が英文としてほぼそのまま読める。真偽値は `is〜` / `has〜` で始めると読みやすい。※命名の話は自分のメモ。
- **`disabled` は「HTML属性」と「JSプロパティ」の両面**から触れる。HTMLでは属性名を書くだけ、JSでは真偽値で操作。同じものを2つの世界から見ている感覚をつかむのが大事。

### 4-13〜4-16｜スクロールのプログレスバー（5ステップ実装）

**何をしたか**
- **4-13 ページのスクロール量を表示しよう（p.130〜131／サンプル `chapter4/13-demo`）**：文章がメインのページは縦に長くなりがちなので、**ページ上部にスクロール量を表す「プログレスバー」** を設置。**「全体でどれくらいのスクロールが必要か」「今どのあたりにいるのか」をユーザーに伝えられる設計にすると親切**。題材は宮沢賢治『銀河鉄道の夜』。
- **4-14 スクロール量を取得しよう（p.132）｜実装のステップ**：**4-14〜4-16 節にまたぐ少し複雑な作業になるので、最初に実装の過程を整理** するという導入。**①プログレスバーを作成 → ②スクロール量を取得 → ③ページのサイズを取得 → ④スクロールされた割合を計算 → ⑤プログレスバーの幅に設定**。以降、この番号が各節の見出しに再登場します。
- **【1】バーを作成（p.132〜133）**：**`bar` という ID のついた空の `<div>`** を用意。CSS では水色の背景と **`position: fixed;` で画面上部に固定**。**現段階では幅の指定がないので何も表示されません**（仮に `width: 100%` を加えると左端から右端まで表示される）。**この幅の値は後ほど JavaScript 側で操作するので、今は記述しないでおく**。
- **【2】スクロール量を取得（p.134〜135）**：**`scroll` イベントは画面をスクロールするたびに発生**し、画面に関することなので **`window`** に設定。**今回は処理の指定が少し長くなりそうなので、関数を用意してイベント発生時に呼び出す書き方** にします（関数名 `getScrollPercent`）。スクロール量は **`window.scrollY`** で、**ページの一番上から垂直方向に何 px スクロールしたか** が返されます。コンソール表示には **テンプレート文字列**（P.068参照）を使用。**POINT：横方向は `scrollX`**。なお **コンソールのメッセージ左横の数字はイベントが発生した回数**（例では213回まで増加）。
- **【3】ページのサイズを取得（4-15／p.136〜138）**：ページ全体の高さはすぐ取得できそうだが、**「スクロール可能な高さ」となると少し計算が必要**。**ページの高さには表示領域（現在表示されている画面）の高さが考慮されていない** からです。ページ2000px・表示領域800pxの例では **1200px スクロールした時点で一番下に到達**。つまり **スクロール可能なページの高さ＝ページ全体の高さ − 表示領域の高さ**（教材のハイライト部）。
- **4-15（続き）2つの高さの取得方法**：ページの高さは **`scrollHeight`**（**画面に表示されていない伸びた部分の高さも含む**）。**ページのルートとなる `<html>` タグの部分は `document.documentElement`** と指定するので、続けて `.scrollHeight`。表示領域のうち **スクロールバーを含まない部分の高さ** は **`clientHeight`**。**POINT：横方向はそれぞれ `scrollWidth` / `clientWidth`**。実測で **5194 − 523 = 4671**（スクロール量）と一致することを検算し、確認できたらテスト用のコンソールはコメントアウト。
- **【4】割合を計算（4-16／p.139〜141）**：計算式は **スクロール量 ÷（ページ全体の高さ − 表示領域の高さ）× 100** で、**現在ページの何％分スクロールしたかを 0〜100 の数値で出せる**。**JavaScript では算数や数学で使う四則演算が利用できる**が記号が少し変わり、**掛け算は `*`（アスタリスク）、割り算は `/`（スラッシュ）**。数値は **P.129「COLUMN 様々なデータの型」** の数値型なのでクォート不要。**数値の計算をするための記号を「算術演算子」と言う**。**優先順位は算数と同じで掛け算・割り算が優先**（`10 + 3 * 2` は26ではなく **16**）、**変えたいときはカッコで囲む**（`(10 + 3) * 2` → 26）。
- **【5】バーの幅に設定（p.142）**：計算した割合を **ID `bar` の横幅（`width`）としてスタイルを付与**。**単位の「%」も必要なのでテンプレート文字列で指定**。これでスクロールするたびに `width` が更新され、**伸縮するプログレスバーが完成**しました。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| 実装のステップ（5段階） | ①バー作成→②スクロール量→③ページサイズ→④割合→⑤幅に設定。複雑な実装は最初に過程を整理する |
| `scroll` / `window.scrollY` / `window.scrollX` | スクロール時に発生するイベント／縦方向のスクロール量（px）／横方向 |
| スクロール可能なページの高さ | **ページ全体の高さ − 表示領域の高さ**。割合計算の分母になる |
| `document.documentElement` | ページのルートとなる `<html>` タグの部分を指す指定 |
| `scrollHeight` / `clientHeight` | ページ全体の高さ（画面外の分も含む）／表示領域のうちスクロールバーを含まない高さ |
| `scrollWidth` / `clientWidth` | ページの横幅／表示領域の幅（POINT で紹介） |
| テンプレート文字列（`` `${}` ``） | バックティックで囲み `${変数}` を埋め込める文字列（教材の呼称。P.068参照） |
| 算術演算子 | 数値の計算をするための記号の総称 |
| 演算子の優先順位 | 掛け算・割り算が足し算・引き算より優先。変えたいときはカッコで囲む |
| `要素.style.プロパティ` | JSからCSSの値を直接書き換える |
| 名前付き関数を渡す | `addEventListener('scroll', 関数名)` のようにカッコを付けずに参照だけ渡す |

**算術演算子の一覧（p.141）**

| 演算子 | 意味 | 例 | 結果 |
|---|---|---|---|
| `+` / `-` | 足し算／引き算 | `10 + 3` / `10 - 3` | `13` / `7` |
| `*` | 掛け算 | `10 * 3` | `30` |
| `/` | 割り算 | `10 / 3` | `3.3333333333333335` |
| `%` | 割り算の余りを計算 | `10 % 3` | `1` |
| `**` | べき乗を計算 | `10 ** 3` | `1000` |

```js
// ===== 4-13／4-16【5】完成形（p.131・p.142／js/script.js） =====
const getScrollPercent = () => {
  // スクロール量
  const scrolled = window.scrollY;

  // ページ全体の高さ
  const pageHeight = document.documentElement.scrollHeight;

  // 表示領域の高さ
  const viewHeight = document.documentElement.clientHeight;

  // スクロールされた割合
  const percentage = scrolled / (pageHeight - viewHeight) * 100;

  // プログレスバーに幅を指定（単位の「%」が必要なのでテンプレート文字列で）
  document.querySelector('#bar').style.width = `${percentage}%`;
};

window.addEventListener('scroll', getScrollPercent);
```

**できるようになったこと**：複雑な実装を **5ステップに分解してから着手する** 進め方。CSS には色・位置・高さだけを書き、**幅は意図的に空けて JavaScript に委ねる** 役割分担。`window` に `scroll` を設定し、処理が長い場合は **名前付き関数を定義して参照だけ渡す** 書き方。`scrollY`／`scrollHeight`／`clientHeight` を取得して **「スクロール可能な高さ＝全体 − 表示領域」** をコンソールで検算する手順。算術演算子6種と優先順位・カッコによる制御。最後に割合を `style.width` に `％` 付きで代入してバーを完成させるところまで。

**つまずき・気づき**
- **「最初に実装のステップを整理する」が最大の学び**。3節にまたがる実装をいきなりコードから始めず ①〜⑤に分解し、各節の見出しに番号を再掲するので **今どのステップにいるかが常にわかる**。日本語で整理してからコードにする作法（4-6／4-9／4-11）の、より大きなスケール版。
- **CSS で `width` を「あえて書かない」設計判断**が明快。**「静的な見た目は CSS、動的に変わる値は JS」** という境界線が引かれている。
- **`scrollHeight` と `clientHeight` の違い**を図で押さえられた。**この2つを引き算して初めて「スクロールできる余地」になる** という発想は言われないと気づきにくい。実測値での検算が説得力がある。
- **コンソール左横の数字がイベント発火回数**だと明示されたのが有益。少しスクロールしただけで213回に到達しており、`scroll` が高頻度で走ることが体感できる。重い処理を書くならカクつき対策（`requestAnimationFrame` で間引く等）が必要。※対策は自分の補足。
- **「まずコンソールに出して確認 → 確認できたら消す」が4回反復**されている。**動作確認用の `console.log` は足場であって成果物ではない** という扱いが徹底されていて、デバッグの型として真似したい。
- **`(pageHeight - viewHeight)` のカッコは必須**。`10 + 3 * 2` が16になる優先順位の話が今回の実装に直結しており、カッコを外すと全く違う結果になる。
- **`%` は「余り」だが正確には剰余（remainder）でモジュロではない**。MDN によれば <cite index="38-1">剰余演算子はその符号が常に被除数（左側）と同じになる</cite>ため `-10 % 3` は `2` ではなく `-1`。<cite index="38-1">正の余りが欲しい場合は `((n % d) + d) % d` と書く</cite>。※符号の話は教材にはない補足。
- **`10 / 3` が `3.3333333333333335` と末尾「5」で終わる**のは誤植ではなく、**浮動小数点数（IEEE 754 倍精度）の表現限界**による。`0.1 + 0.2 !== 0.3` と同根。教材がこの値をそのまま載せているのは正直で良い。※誤差の説明は自分の補足。
- **4-13 で関数を分けた理由がここで明示された**：「処理の指定が少し長くなりそうなので」。**処理の分量で無名関数と名前付き関数を使い分ける** という判断基準だった。

### 6-1〜6-3｜動きの実例・効果・心地よさの条件（p.200／p.204〜207）

**何をしたか**

- **6-1 動きがあるWebサイトを見てみよう（p.200）**：撮影範囲では **六角館さくら堂KYOTO**（化粧筆専門店／ https://www.rokkakukan-sakurado.com/ ）を紹介。優しい色合いとふんわりした動きで化粧筆の質感を表現している。挙がっていた動きは、**カーソルにあわせて商品写真や桜の花びらがゆっくり移動**する表現と、**下からスッとではなく波のように左から右へ順に現れる**表現の2つ。
- **6-2 なぜ動きがあると効果的なのか（p.204〜205）**：「なんとなく格好がいいから」だけならここまで広がらなかったはず、という切り口でメリットを3つに整理。
  - **① 状態が変化したことを知らせる**：画面がパッと変わると何が起こったかわからない。現実世界では物が突然現れたりしない。**アニメーションをうまく活用すれば、最初から最終の状態までの変化を自然に表現できる**。例＝積水ハウス「家づくりのあるあるFACT BOOK 2022」。紙芝居のように画面をめくって各セクションを遷移させる。
  - **② ユーザーが今何をしているのかを表示できる**：突然動かなくなったとき、回線切れか読み込み中か判断できないと対処できない。**アニメーションはユーザーの状況を視覚的に伝えられる優れた手段の1つ**。例＝Dropbox（選択ファイル・進捗・完了をアニメーションとアイコンで表示）。
  - **③ 使い方を端的に説明する**：「どこを見て」「何をすべきか」を伝えると初めてのユーザーも安心して使える。例＝CodePen（保存しないまま書き続けると「Save」ボタンが一定回数揺れる）。
- **6-3 心地よいと感じる動きとは（p.206〜207）**：心地よいアニメーションには「アニメーションだと気づかせない自然さ」がある。条件は5つ。
  - **タイミングと速度**：ユーザー操作起点なら操作終了後に速やかに動き出すのが理想。速すぎると気づけず、遅すぎると待たせる。**100ミリ秒（0.1秒）より速い動きはアニメーションだと認識されづらい**。
  - **動かすものの数**：**「動かすものの数を絞る」「同時に多くのものを動かさない」**のが不快にさせないポイント。複数なら順番を決める、速度に強弱をつける。
  - **再生回数**：どんなに良くてもずっと見ているとうっとうしい。無限ループは可能だが**再生回数を考える**必要がある。
  - **加減速（イージング）**：現実の物体は一定速度では動かず、**少しゆっくり開始 → だんだん加速 → 終了時に再び減速**するのが自然。
  - **デザインテーマに合わせる**：例＝柔らかな寝具サイトなら、ピョンピョン跳ねるよりふわふわ浮かび上がる表現。
- **COLUMN getElementByで要素を取得する（p.207）**：

| 目的 | querySelector 系 | getElementBy 系 |
|---|---|---|
| 特定のidのついた要素を取得 | `querySelector('#ID名')` | `getElementById('ID名')` |
| 特定のクラスのついた要素をすべて取得 | `querySelectorAll('.クラス名')` | `getElementsByClassName('クラス名')` |
| 特定のタグを使った要素をすべて取得 | `querySelectorAll('タグ名')` | `getElementsByTagName('タグ名')` |

  結論：`querySelector〜` は **CSSのセレクター感覚**で書け、`:hover` `:first-child` などの**疑似クラスも使える**。`getElementBy〜` は処理が早いが**体感するほどではない**ため、`querySelector()` / `querySelectorAll()` で統一する方が書きやすい。

**つまずき・気づき**

- 6-2の3つのメリットは、そのまま**アニメーションを入れるかの判断基準**になる。「状態変化の説明」「進捗の可視化」「使い方の誘導」のどれにも当てはまらない動きは、装飾以上の意味を持っていない可能性が高い。
- 「100ミリ秒」は下限の目安。※上限は教材に記載がなく「内容や動かすものによって変わるので一概には言えない」とされている。
- ※教材の表（p.207）は2行目が `getElemetnsByClassName` と読める綴りだが、**正しくは `getElementsByClassName`**（MDN で確認）。上表は修正して記載した。

### 6-4〜6-7｜見出しを下から浮き上がらせよう（p.208〜219）

**何をしたか**

- **6-4 作るもの（p.208〜209）**：見出しが下からふわっと表示されるアニメーション。サンプルは `chapter6/04-demo`（`index.html` / `js/script.js` / `css/style.css`）。動きは「**見出しが透明 → 下からふわっと浮かぶ → 表示完了**」の3段階。HTMLは `<h1 id="heading">JavaScriptでアニメーション</h1>` のみ、CSSは `body { text-align: center; }` のみ。

```javascript
// js/script.js（6-4 完成形）
const heading = document.querySelector('#heading');

const keyframes = {
  opacity: [0, 1],
  translate: ['0 50px', 0],
};
const options = {
  duration: 2000,
  easing: 'ease',
};

heading.animate(keyframes, options);
```

- **6-5 Web Animations APIとは（p.210）**：**WAAPI は、他のライブラリーを使わずにアニメーションを実装できるJavaScriptの仕様**。CSSのプロパティと値のように「要素の何を変化させるか」を指定し、**開始時と終了時の値さえ指定すれば、その2点の間の値を自動補完**してなめらかに動かす。この自動補完される動かす内容を**キーフレーム**と呼ぶ（例：透明→不透明なら中間地点は透明度50%）。
- **6-5 基本の書き方（p.210〜211）**：動かしたい要素に `animate()` を加え、**第一引数＝動かす内容（キーフレーム）／第二引数＝再生時間**を「,」で区切る。第一引数は**オブジェクト**で、CSSの「-」が付くプロパティは**「-」を除いて大文字表記**（例：`font-size` → `fontSize`）。値は開始点・終了点を **「[ ]（角カッコ）」で囲んで配列**にする。第二引数は**ミリ秒**（1秒＝`1000`）。

```javascript
// ① 直接記述
動かす要素.animate({
  キー（プロパティ名）: ['開始の値', '終了の値'],
}, 再生時間);

// ② 定数にまとめて呼び出す（定数名は自由）
const keyframes = {
  キー（プロパティ名）: ['開始の値', '終了の値'],
};
動かす要素.animate(keyframes, 再生時間);
```

- **6-5 opacity で徐々に表示（p.212〜213）**：ID `heading` を定数に入れ、`heading.animate(keyframes, 2000)` と書く。第一引数はまだ未記述なので現時点ではエラー。次に `keyframes` を用意し、キーに `opacity` を記述。**開始時の `0` は不透明度0%＝透明、終了時の `1` は100%＝不透明**。**単位のいらない値なので数値として扱い、クォーテーションは不要**。→ 2秒かけて見出しが表示される。
- **6-6 複数のアニメーション（p.214〜215）**：1つの要素に複数の動きを加えるには、**オブジェクト形式で新たなプロパティを「,」区切りで追加するだけ**。**配列の中にオブジェクトを書く形式**もあり、一度に動く内容が多い場合はそちらの方がわかりやすい。今回は前者で `translate` を追加し、**開始時 `'0 50px'`（横0・縦50px下）→ 終了時 `0`（元の位置）** とする。→ 透明だった見出しが下からふわっと浮き出る。
  - **POINT**：**値が0の場合は単位不要なのでクォーテーションで囲っていない**。`'0'` と囲んでも動作は同じ。

```javascript
// 形式B：配列の中にオブジェクト
const keyframes = [
  { プロパティ1: '開始の値1', プロパティ2: '開始の値2' },
  { プロパティ1: '終了の値1', プロパティ2: '終了の値2' }
];
```

- **6-7 動きの詳細（タイミング）（p.216〜219）**：第二引数には再生時間だけでなく**タイミングや繰り返しのオプション**も指定でき、その場合は**オブジェクト形式**にする。直接書くと内容と詳細の区別がつきにくいので、**別途 `options` という定数にまとめて呼び出す**とわかりやすい。**数値でない値は文字列なのでクォーテーションで囲む**。**必須項目は `duration` のみ**。

| プロパティ | 内容 | 初期値 |
|---|---|---|
| `delay` | 開始を遅らせる時間。整数値のミリ秒 | `0` |
| `direction` | 実行する方向 | `normal` |
| `duration` | 再生時間。**必須**。整数値のミリ秒 | ─ |
| `easing` | 変化する速度やタイミング | `linear` |
| `fill` | 再生前後の状態 | `none` |
| `iterations` | 繰り返す回数。無限ループは `Infinity` | `1` |

- **direction**：`normal`（通常＝初期値）／`alternate`（奇数回で通常・偶数回で反対方向＝行って帰って）／`reverse`（逆方向）／`alternate-reverse`（alternateの逆方向）
- **easing**：`linear`（一定速度＝初期値）／`ease`（開始時と終了時は緩やか）／`ease-in`（最初ゆっくり→速く）／`ease-out`（最初速く→ゆっくり）／`ease-in-out`（開始・終了がかなり緩やか）／`steps()`（段階ごと）／`cubic-bezier()`（ベジェ曲線に沿う）
- **fill**：`none`（なし＝初期値）／`forwards`（再生後、最後のキーフレームの状態を保持）／`backwards`（再生前、最初のキーフレームの状態を適用）／`both`（両方）
- **POINT**：`Infinity` はクォーテーションで囲まず**1文字目を大文字**にする。`"Infinity"` や `infinity` では動作しない。
- 最後に `duration: 2000` と `easing: 'ease'` を `options` にまとめて完成。→ 前節までスーッと表示されていた見出しが、**最初はゆるやか → 中間で勢いがつく → 最後はスピードダウン**して表示されるようになった。

**つまずき・気づき**

- 「開始と終了だけ書けば間は勝手に埋まる」＝**自動補完**がWAAPIの肝。CSSの `@keyframes` で `0%` `100%` を書くのと同じ発想がJS側のオブジェクトに移っただけ、と捉えると理解しやすい。
- `keyframes` `options` という定数名は**教材が便宜的に付けているだけで自由に変えてよい**と明記（p.211／p.217）。役割で覚え、名前で覚えない。
- 第二引数は**数値なら再生時間、オブジェクトならタイミング指定一式**という二重の意味を持つ。`animate(keyframes, 2000)` は `{ duration: 2000 }` の省略形と理解しておくと混乱しない。
- 6-3で学んだ「イージング」が6-7で `easing: 'ease'` という具体的なコードに接続される。**設計の話（前半）→ 実装の話（後半）**という章の作りが明確。
- ※教材は `Infinity` を「JavaScriptの**予約語**」と説明するが、MDNでは**グローバルオブジェクトのプロパティ（グローバルスコープの変数）**であり `if` や `class` のような予約語ではない。書き方の結論自体は正しい。
- ※`translate` はCSSの独立したトランスフォームプロパティで、MDNによると**主要ブラウザーで利用可能になったのは2022年8月**。`transform: translate()` とは別物で、`translate` → `rotate` → `scale` → `transform` の順に適用される。
- ※`easing` の初期値は**WAAPIでは `linear`**（教材どおり）だが、**CSSアニメーション（`animation-timing-function`）の初期値は `ease`** で混同しやすい。

### 6-8｜色々な見出しのアニメーション（p.220〜223）

**何をしたか**

HTML／CSSをほぼそのまま使い、キーフレームとオプションを差し替えるだけで4種類を作る節。

- **① くるっと回転（08-demo1）**：`rotate: ['x 360deg', 0]` を追加。**X軸で360度回転**し、終了時は `0`（定位置）に戻る。`duration: 1000` / `easing: 'ease'`。
- **② 色が変化（08-demo2）**：文字色を4色用意し「,」で区切る。**開始と終了の2値だけでなく、複数の変化がある場合はこのように記述できる**。折り返すため `direction: 'alternate'`、ずっと繰り返すため `iterations: Infinity`。

```javascript
const keyframes = {
  color: ['#f66', '#fc2', '#0c6', '#0bd']
};
const options = {
  duration: 8000,
  direction: 'alternate',
  iterations: Infinity,
};
```

→ 赤→黄色→緑→水色と変化し、水色まできたら緑→黄色→赤と折り返す。

- **③ 背景が伸びる（08-demo3）**：CSSの `linear-gradient` で**くっきり境目のある水色と白の2色**を敷き、その境目をJSの **`backgroundPosition`** で動かして四角形が伸びたように見せる。文字色も `transparent` → `#fff` に。

```css
h1 {
  color: #fff;
  display: inline-block;
  background-image: linear-gradient(90deg, #0bd, #0bd 50%, #fff 50%, #fff);
  background-size: 200% 100%;
  padding: .5rem 1rem;
}
```

```javascript
const keyframes = {
  color: ['transparent', '#fff'],
  backgroundPosition: ['100% 0', '0 0'],
};
```

- **④ ふよふよ動く（08-demo4）**：四隅の角丸を `borderRadius` で指定。**楕円の横の半径と縦の半径を「/（スラッシュ）」で区切り、左上・右上・右下・左下の順に時計回り**で書く。値に少しずつ変化をつけると**流体シェイプ**になる。CSSは `border-radius: 50%` の円形がベース。

```javascript
const keyframes = {
  borderRadius: [
    '20% 50% 50% 70%/50% 50% 70% 50%',
    '50% 20% 50% 50%/40% 40% 60% 60%',
    '50% 40% 20% 40%/40% 50% 50% 80%',
    '50% 50% 50% 20%/40% 40% 60% 60%',
  ],
};
// options は ② と同じ（8000 / alternate / Infinity）
```

**つまずき・気づき**

- **配列の値は2つとは限らない**のが6-5からの重要な拡張。要素数を増やせば**その数だけ等間隔の中間地点**が置かれる。
- ③はJSで動かすのは `backgroundPosition` だけで、見た目の主役（グラデーションの境目）はCSS側にある。**CSSで状態を作り、JSで位置だけ動かす**という分業パターンとして再利用しやすい。
- ※`rotate` も `translate` と同じ**CSSの独立したトランスフォームプロパティ**。`'x 360deg'` は軸と角度をスペース区切りで書く書式で、`transform: rotateX(360deg)` に相当する。

### 6-9〜6-11｜複数の画像を順番に表示しよう（p.228〜235）

**何をしたか**

- **6-9 作るもの（p.228〜229）**：複数画像を1枚ずつふんわり表示する。**表示までの時間を少し変えるだけで実装できる**。サンプルは `chapter6/09-demo`（`images/summer1.jpg` 〜 `summer6.jpg`）。HTMLは `class="img-item"` の `<img>` を6つ、`.grid` で並べる。CSSは `.img-item { opacity: 0; }` で初期状態を透明にしておく。

```javascript
// js/script.js（6-9 完成形）
const items = document.querySelectorAll('.img-item');

for (let i = 0; i < items.length; i++) {
  const keyframes = {
    opacity: [0, 1]
  };
  const options = {
    duration: 600,
    delay: i * 300,
    fill: 'forwards',
  };
  items[i].animate(keyframes, options);
}
```

- **6-10 querySelector() の限界（p.230〜231）**：ここまではID属性で要素を指定してきたが、今回は**クラス属性**。`querySelector('.img-item')` で書くと**最初の1つしか現れない**。これは `querySelector()` が、**複数のHTML要素が見つかった場合に最初の1つしか取得できない**ため。
- **6-10 querySelectorAll() と NodeList（p.232）**：すべて取得したい場合は **`querySelectorAll()`**。使い方は同じでカッコの中にCSSセレクターを書く。`console.log()` で見ると **`NodeList(6)`** が返る。**NodeList は配列形式のデータ**で、展開すると `0: img.img-item` 〜 `5:`、`length: 6` という配列の形になっている。**配列ということは、1つひとつ個別に取得するため `for` 文が必要**。
- **6-10 for文で全要素へ（p.233）**：通常の配列と同じく **`length`** で要素数を取得できる。インデックスで個別に取得するため **`items[i]`** とする。確認用の `console.log()` はコメントアウト。→ すべての画像がふわっと表示された（ただし**この段階では全部同じタイミング**）。
- **6-11 delayで1つずつ遅延（p.234〜235）**：**`delay` はアニメーションの開始時間を遅らせる**もので整数値のミリ秒（0.3秒なら `300`）。ただし単純に `delay: 300` と書くと**全画像が0.3秒遅れて「同時に」表示されるだけ**。1枚ずつずらすには**値に `i` をかける**。

| 画像 | 計算 | 遅延 |
|---|---|---|
| 1枚目 `items[0]` | `0 × 300` | 0秒（ページ読み込みと同時） |
| 2枚目 `items[1]` | `1 × 300` | 0.3秒 |
| 3枚目 `items[2]` | `2 × 300` | 0.6秒 |

→ **WAAPI では変数をアニメーションに組み込んで指定できる**ため、表現の幅がグンッと広がる。

**つまずき・気づき**

- 6-10は**あえて失敗するコードを先に書かせて、症状から原因に辿らせる**構成。「1つしか動かない」という症状を見たら `querySelector` / `querySelectorAll` の取り違えを疑う、という診断パターンとして覚えておく。
- `fill: 'forwards'` が必須なのは、CSS側で `.img-item { opacity: 0; }` としているため。**指定しないと終了後にCSSの透明に戻ってしまう**。6-7の表で見た `fill` がここで初めて「なくてはならないもの」になる。
- 6-11がこの章一番の効きどころ。**オプションの値は固定値でなくループ変数を使った式が書ける**。CSSアニメーションで同じことをやるには `nth-child` ごとに `animation-delay` を並べる必要があり、ここがWAAPIを使う実利。
- `delay: 300` ＜ `duration: 600` なので前の画像がまだ動いている途中に次が始まり、動きが途切れず繋がる。6-3の「順番を決める」という指針とも整合している。
- ※`querySelectorAll()` が返す **NodeList は配列そのものではない**（配列風オブジェクト）。`length`・インデックス・`forEach()` は使えるが `map()` や `filter()` は直接使えない。`for` 文を使う範囲では違いは表面化しない。

### 6-12〜6-13｜色々な画像のアニメーション／スクロールとの組み合わせ（p.236〜241）

**何をしたか**

- **6-12（p.236〜239）**：6-9と同じHTMLで、`keyframes` に1〜2行足すだけで見え方を変える4パターン。オプションは共通で `duration: 600` / `delay: i * 300` / `fill: 'forwards'`。

| デモ | 追加したキーフレーム | 見え方 |
|---|---|---|
| 回転（12-demo1） | `rotate: ['x 90deg', 0]` | 横軸に90度回転しながら表示。1行でかなりダイナミックに |
| 下から浮き上がる（12-demo2） | `translate: ['0 50px', 0]` | P.208「6-4」と同じ動き。1つずつ浮き上がる |
| ふわふわ落ちてくる（12-demo3） | `rotate: ['5deg', 0]` ＋ `scale: [1.1, 1]` | 落ち葉が上からふわりと落ちるような動き |
| ぼかしが晴れる（12-demo4） | `filter: ['blur(20px)', 'blur(0)']` | ぼけた画像の霧が少しずつはれる爽快感 |

- **値の書き方の整理（p.238）**：**`rotate` は単位が必要なのでクォーテーションで囲んで文字列**にするが、**値が0の場合は不要**。**`scale` は拡大率で単位不要なのでクォーテーションなしの数値**として扱う。
- 12-demo4 はCSS側で `.img-item { filter: blur(20px); }` と初期状態をぼかしておく。**filter は他にも `brightness()`（明度）、`saturate()`（彩度）、`grayscale()`（白黒）**など様々な効果がある（教材がMDNの `filter` ページを参照先として明示）。
- **6-13 スクロールとアニメーションを組み合わせよう（p.240〜241）**：スクロールと連動して要素が表示される仕掛けは、シンプルなものなら少ないコードで実装できる。サンプルは `chapter6/13-demo`。**キリンの画像が表示領域内に入ると右端からふわっと表示**される。CSSは `h1 { margin: 50vh 0 50vh; }` でスクロールが必要な高さを作っているだけ。

```html
<body>
    <h1>↓ スクロール ↓</h1>
    <img src="images/kirin.jpg" id="kirin" alt="キリン">
</body>
```

```javascript
// js/script.js（6-13 完成形）
// 監視対象が範囲内に現れたら実行する動作
const showKirin = (entries) => {
  const keyframes = {
    opacity: [0, 1],
    translate: ['200px 0', 0],
  };
  entries[0].target.animate(keyframes, 600);
};

// 監視ロボットの設定
const kirinObserver = new IntersectionObserver(showKirin);

// #kirinを監視するよう指示
kirinObserver.observe(document.querySelector('#kirin'));
```

**つまずき・気づき**

- 6-12は**「HTMLもオプションも固定して、キーフレームだけ差し替える」練習**。6-8（見出し）と対になっており、**変えるべき場所が1箇所に集まっている設計**だと試行錯誤が速いと実感できる。
- クォーテーションの要否は「**単位を伴う値＝文字列（要クォート）／単位なしの数値＝そのまま**」で一貫している。`opacity: [0, 1]`・`scale: [1.1, 1]` はクォートなし、`rotate: ['5deg', 0]`・`filter: ['blur(20px)', ...]` はクォートあり、`0` はどちらでも可。

### 6-14〜6-16｜Intersection Observerの仕組み／交差状態の情報／動きを加える（p.242〜251）

**何をしたか**

- **6-14 ベースのHTML/CSS（p.242）**：6-13で提示した完成形をここから分解して組み立て直す。HTMLはキリンの画像に **`kirin` というIDを付与**するだけ。CSSは**スクロール時の動作がわかりやすいよう見出しの上下に多めの余白をとっているだけで特別な指定はない**。
- **6-14 Intersection Observer APIとは（p.243）**：
  - 従来は P.132「4-14」で紹介した **`scroll` イベント**を使っていたが、**画面サイズが変わると再計算が必要**だったり、**スクロールのたびに関数を呼ぶのでパフォーマンスへの悪影響が懸念**されていた。
  - 「特定の要素が監視領域に入ったら動作すればいい」場合は **Intersection Observer（交差の監視者）** が使える。**特定の要素が指定領域内に入ったかどうかを検知するJavaScriptの機能の1つ**で、この状態を**「交差している」**と表現する。検知すると**事前に用意しておいた関数を呼び出す**。`scroll` と違い**スクロールのたびに反応するわけではない**ので、ブラウザーへの負担が少ない。
  - 用語の対応：**監視領域**＝ブラウザーの表示領域／**監視対象**＝キリンの画像／**交差**＝両者が重なった状態。教材は「**動物園に監視ロボットを導入し、草食動物エリアにキリンが入ってきたら『キリンさんです』と知らせる**」というストーリーで説明している。
- **6-14 基本の書き方は4ステップ（p.244〜246）**：

| ステップ | 内容 | コード |
|---|---|---|
| ① | 監視ロボットに、して欲しい内容を決めておく | `const showKirin = () => { ... };` |
| ② | 新しい名前をつけて監視ロボットを導入する | `const kirinObserver = new IntersectionObserver();` |
| ③ | 監視ロボットに①で決めた動作内容を指示する | `new IntersectionObserver(showKirin)` |
| ④ | 監視ロボットに監視対象を教えて実行する | `kirinObserver.observe(document.querySelector('#kirin'));` |

  - **②**は「市販されている他の監視ロボットと区別するために、名前をつけて初期設定するようなもの」。**④**の時点までは初期設定だけで**スタートボタンを押していない**状態で、**`observe()`**（＝「監視する」）を呼んで初めて監視が始まる。さらに**カッコの中に「何を監視するか」**を渡す必要がある。
- **6-14 実行タイミング（p.246）**：コンソールで確認すると、Intersection Observer は**以下の3つのタイミングで関数が実行される**。
  1. **監視が始まったとき**（ページ読み込み直後に一度出力される）
  2. **監視対象がエリア内（画面）に入ったとき**（画像が少しでも表示された瞬間）
  3. **監視対象がエリア内（画面）から出たとき**（画像が完全に見えなくなった瞬間）
- **6-15 監視対象の情報を取得する（p.247〜248）**：監視ロボットは**監視対象のサイズや名前、エリアに入っているかどうかもすべて把握できる**。これは**関数が呼び出されるときに、交差状態の情報を含むオブジェクトが引数として自動的に渡される**から。**監視対象が複数の場合もあるので配列で渡される**。関数の丸カッコに **`entries`** と書き加えると受け取れる（**名前は慣習で、変更しても動作する**）。

```javascript
const showKirin = (entries) => {
  console.log(entries);     // → [IntersectionObserverEntry]
};
```

  - 展開すると `0: IntersectionObserverEntry {…}`、`length: 1`。**今回は1つしかないのでインデックス0番目だけ**なので、`entries[0]` と書き換える。さらに展開すると情報が**オブジェクトとしてまとめられている**。これは P.185「5-10」で学習した**配列の中にオブジェクトが入っている状態**。
- **6-15 IntersectionObserverEntry の主なプロパティ（p.249）**：

| プロパティ | 意味 |
|---|---|
| `boundingClientRect` | 監視対象の要素のサイズや位置。`top, bottom, left, right, width, height, x, y` が参照可能 |
| `intersectionRect` | 監視対象の要素が**表示されている部分**のサイズや位置。同上 |
| `intersectionRatio` | 監視領域と交差している**割合**。0〜1の数値 |
| `isIntersecting` | 監視対象が監視領域に**入っているかどうか** |
| `rootBounds` | **監視している領域**のサイズや位置。同上 |
| `target` | **監視対象の要素** |
| `time` | 交差が記録された時刻（ミリ秒） |

  - この表をもとに出力を読むと、**横幅1200px・高さ800px、この時点で交差していない、ID名 kirin の img 要素**…とわかる。**細かい指定はCHAPTER 7で試すので、今は「色々な情報が取得できるのだな」でOK**。今回ほしいのは要素そのものなので **`target`** を**ドット記法**（P.180「5-9」）で指定する。

```javascript
console.log(entries[0].target);
// → <img src="images/kirin.jpg" id="kirin" alt="キリン">
```

- **6-16 動きを加えてみよう（p.250〜251）**：P.210「6-5」を参考に、`keyframes` に `opacity` と、**右側200pxの位置から移動させるための `translate`** を記述。**監視対象である `entries[0].target` に `animate()`** で動かす内容と再生時間を指定する（コンソール出力は消す）。再生時間 `600` で**0.6秒かけてふわっと表示**。→ **スクロールに応じたアニメーションの完成**。**次のCHAPTER 7では複数の要素を扱う書き方**が紹介される。

```javascript
const showKirin = (entries) => {
  const keyframes = {
    opacity: [0, 1],
    translate: ['200px 0', 0],
  };
  entries[0].target.animate(keyframes, 600);   // ← 追加した
};
```

**つまずき・気づき**

- **6-13で完成コードを見せ → 6-14〜6-16で分解して組み直す**構成。4-14〜4-16のプログレスバーと同じ「先に全体、あとから部品」パターンで、この教材の型として定着してきた。
- `scroll` との対比が要点。**「スクロール量を毎回計算する」から「ブラウザーに交差を判定させる」への発想の転換**で、パフォーマンスと画面サイズ変更への耐性を同時に得ている。
- 「監視ロボット」の比喩は **①動作を決める → ②ロボットに名前をつける → ③やることを教える → ④監視対象を教えてスイッチを入れる** に対応。特に **②③④が別ステップである（＝`new` した時点ではまだ何も動かない）** ことが理解の分かれ目。
- `entries` が**配列なのは「監視対象が複数の場合もあるから」**と明記されている。今回は1つなので `entries[0]` で済むが、複数なら `forEach` 等になるはず（CHAPTER 7で扱われる見込み）。
- ※MDNによると **`observe()` を呼んだ直後に必ず1回コールバックが発火**し、**画面外に出て再び入るたびに再発火**する。これは教材 p.246 の「3つのタイミング」と一致する。裏を返すと、**入ったときだけ動かしたいなら `isIntersecting` の判定や `unobserve()` が必要**で、教材のサンプルはそこまで踏み込んでいない（スクロールで往復すると再生が繰り返される）。
- ※教材 p.250 本文は `opacity: [0, 1]` を「**透明から半透明にする**」と説明しているが、`1` は**不透明**（p.213 の本文とも矛盾する）。**「透明から不透明」が正しい**と考えられ、誤植の可能性が高い。
- ※コンソール出力に見える `isVisible` は教材の表に載っていない。MDNでは **`trackVisibility` オプションを有効にしたときに意味を持つ**プロパティで、既定では常に `false`。

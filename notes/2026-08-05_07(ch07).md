### 7-2〜7-4｜ローディングから画面遷移（`animate()`・`delay`・`offset`）（p.259〜272）

**何をしたか**
- **ねらい（7-2／p.259）**：**読込中に真っ白な画面が続くと不安になる**ので、**読込中だと認識できるローディングアニメーション**を入れる。**「Loading」の文字を出すだけでなく、淡い緑色のスクリーンを下から上に移動させながら、徐々にローディング画面を透明にしてコンテンツをふんわり表示**していきます。完成コードが先に丸ごと提示され、7-3以降で分解して組み立てる構成。
- **グレースクリーンを作る（7-3／p.262〜265）**：`<body>` の一番上に **`loading` という ID の `<div>`** を追加し、CSSで `position: fixed` ＋ `inset: 0` ＋ `z-index: 9999` ＋ `place-items: center` で画面いっぱいに広げる。**P.094「4-2」を参考に `window` の `load` イベント**を用意し、`#loading` を定数 **`loadingAreaGrey`** に格納して **`animate()`** を呼ぶ。**カッコの中には「動かす内容」と「動きの詳細」をカンマで区切って指定**。`opacity: [1, 0]` に加えて **`visibility: 'hidden'` を指定することで、アニメーション終了時に要素を非表示にしてクリックできない状態**にします。**`delay: 1200` は、この後の薄緑スクリーンのアニメーションが終わってから透明度を変えるための設定**。
- **薄緑スクリーンを動かす（7-3／p.265〜267）**：`#loading` の中に **`loading-screen`** を追加。**ポイントは `translate` プロパティで縦方向に `100vh` を指定し、画面外の見えない下側に設置しておくこと**。JS側では定数 **`loadingAreaGreen`** に入れ、`translate` を **`['0 100vh', '0 0', '0 -100vh']`**（画面外・下 → 画面いっぱい → 画面外・上）と3段階で変化させ、**画面下から現れて上に移動していく表現**を作ります。
- **テキストとタイミング調整（7-4／p.268〜272）**：`#loading` の中に `<p>Loading...</p>` を追加し、定数 **`loadingText`** で `opacity` を0にするアニメーションを指定。ただし **表示された瞬間に透明になり始めるため、読まないうちに消えてしまう**。そこで **`offset`** を使う。**デフォルトではキーフレームは等間隔で実行されるが、`offset` を指定すると任意のタイミングで実行できる。値は 0.0（開始）〜1.0（終了）**。**オブジェクト形式と配列形式の2通りのうち配列形式に書き換える**と（**タイミングごとの動きの内容が把握しやすくなる**）、各波カッコに `offset` を足せます。**POINT：小数は一の位の「0」を省略して `.8` とも書ける**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `要素.animate(動かす内容, 動きの詳細)` | 第1引数に変化させる内容、第2引数にタイミング。**カンマで区切る** |
| `duration` / `delay` / `easing` / `fill: 'forwards'` | 所要時間／開始を遅らせる時間／緩急／終了後も最後の状態を保持 |
| `opacity` / `visibility: 'hidden'` | 透明度の変化／終了時に非表示にしてクリックできない状態にする |
| `translate: 0 100vh` | 個別トランスフォームプロパティ。**横 縦** の順で移動量を指定 |
| `vh` / `vw` | 画面の高さ／幅を100とした単位。`100vh` は画面1つ分 |
| `inset: 0` ＋ `position: fixed` | 要素を画面いっぱいに広げる定番（4-3で既出） |
| `offset`（キーフレーム） | そのキーフレームを再生時間のどこに置くかを **0.0〜1.0** で指定 |
| オブジェクト形式／配列形式 | `{opacity: [1,0]}` ／ `[{opacity:1},{opacity:0}]`。後者はタイミングを細かく制御しやすい |
| `.8` という書き方 | 小数は一の位の `0` を省略できる |

**学んだ主な構文**

```css
/* ===== 7-3 css/style.css（p.263・p.266） ===== */
#loading {
    background-color: var(--light-grey);
    position: fixed;
    inset: 0;                    /* 画面いっぱいに広げる */
    z-index: 9999;
    display: grid;
    place-items: center;
}
#loading-screen {
    background-color: var(--light-green);
    position: fixed;
    inset: 0;
    z-index: 9998;
    translate: 0 100vh;          /* 画面外（下側）に待機させておく */
}
#loading p {
    font-size: 2rem;
    font-family: var(--oswald-font);
}
```

```js
// ===== 7-2〜7-4 ローディング部分の最終形（p.259〜260／js/script.js） =====
const loadingAreaGrey  = document.querySelector('#loading');
const loadingAreaGreen = document.querySelector('#loading-screen');
const loadingText      = document.querySelector('#loading p');

window.addEventListener('load', () => {
  // ローディング中（グレースクリーン）
  loadingAreaGrey.animate(
    { opacity: [1, 0], visibility: 'hidden' },
    { duration: 2000, delay: 1200, easing: 'ease', fill: 'forwards' }
  );

  // ローディング中（薄緑スクリーン）
  loadingAreaGreen.animate(
    { translate: ['0 100vh', '0 0', '0 -100vh'] },   // 下 → 全画面 → 上
    { duration: 2000, delay: 800, easing: 'ease', fill: 'forwards' }
  );

  // ローディング中テキスト（配列形式＋offsetで後ろに寄せる）
  loadingText.animate(
    [
      { opacity: 1, offset: .8 },   //80%までは不透明のまま
      { opacity: 0, offset: 1  },   //100%
    ],
    { duration: 1200, easing: 'ease', fill: 'forwards' }
  );
});
```

**できるようになったこと**：`window` ＋ `load` の中で **`animate()` を要素ごとに呼び、`delay` で前後関係を作る**設計。**CSSで初期位置（`translate: 0 100vh`）を決め、JSで動かす**という役割分担。`offset` で **「いつ変化させるか」を再生時間の割合で指定**し、`duration` を伸ばすのではなく **変化を後ろに寄せて「表示 → 少し待つ → 消える」を作る**手法。

**つまずき・気づき**
- **`delay` で振り付けをしている**のが最大の学び。グレー1200 / 薄緑800 / テキスト0 と、**1つのタイムラインを3つの `animate()` に分割**している。時間を並べると、テキストが消え終わる1200msからグレーが薄れ始め、薄緑は800→2800msで画面を下から上へ通過する噛み合わせ。※計算は自分の補足。
- **`visibility: 'hidden'` を書いても途中で急に消えない理由**。MDNによれば <cite index="20-1">visibility はアニメーション時、visible と not-visible の間で補間され、離散的なステップとして補間されるが、イージング関数の 0〜1 の間の値はすべて visible になる</cite>。つまり **アニメーション中は表示されたままで、終了時に初めて hidden になる**ので `opacity` のフェードを邪魔しない。
- **`duration` を延ばすのと `offset` を後ろへ寄せるのは別物**。前者は「ゆっくり薄くなる」だけで、**読ませたい"止まっている時間"は作れない**。`offset: .8` は前半80%を"変化なし"に確保する指定で、`@keyframes` の `0%, 80% { opacity: 1 }` と同じ発想。
- **`offset` には制約がある**。MDNによれば <cite index="1-1">offset の値は 0.0〜1.0（両端を含む）でなければならず、昇順に並べる必要がある</cite>。
- **`fill: 'forwards'` を3つとも付けている**のが重要。これがないと終了と同時に元のCSSの状態に戻り、**ローディングが終わったのに画面が覆われたまま**という事故になる。

### 7-5〜7-8｜画像ギャラリー（`querySelectorAll`・`event.target`・`forEach`）（p.278〜291）

**何をしたか**
- **ねらい（7-5／p.278）**：**サムネイル画像にマウスカーソルをあわせるだけで大きく表示できると便利**で、**アニメーションと組み合わせるとドラマチックな表現にもできる**。動きは **カーソルをあわせると左側の大きな画像が一瞬パッと消えたかと思うと、少しずつ選択した画像が表示されていく**というもの。**複数のHTML要素を取得する際は `forEach` というループの書き方にも挑戦**します。HTMLは `.gallery-image`（大きい画像）＋ `.gallery-thumbnails`（`<li>` に9枚のサムネイル）。
- **複数要素の取得（7-6／p.281）**：大きい画像を `mainImage`、複数の小さい画像を `thumbImages` に格納。**複数の画像には `querySelector` ではなく `querySelectorAll` を使う点に注意**。コンソールでは **`NodeList(9)` と表示され、`length` が `9`** になっていることを確認。**配列で取得されたHTML要素は P.230「6-10」の通り `for` で個別に展開できる**ので、`thumbImages.length` と変数 `i` で回します。
- **ホバーで光らせる（7-6／p.282〜283）**：**1つひとつの画像は `thumbImages[i]`** なので、それに `addEventListener` で **`mouseover`**（マウスカーソルが重なった）を指定。`console.log` で確認後、**`mainImage.animate({opacity: [0, 1]}, 500)`** に差し替え。**あらかじめ表示されていた大きい画像が一瞬不透明度0（＝透明）になって消えたような状態となり、その後少しずつ不透明に変化していく**＝**パッと光るような印象**になります。ただし **この時点ではどのサムネイルでも左側の画像は変わらないまま**。
- **イベントオブジェクト（7-7／p.284〜287）**：**`addEventListener()` を使う場合、引数として発生したイベントに関する情報が含まれるオブジェクトが自動的に渡される。これを「イベントオブジェクト」と呼び、慣習的に `event` や `e` という名前がよく使われる**（任意の名前でよい）。コンソールに出すと **`MouseEvent`** が表示され、その中の **`target`（イベントを発生させたHTML要素）** を使う。`event.target` → カーソルを乗せた `<img>`、**`event.target.src`** → その画像のファイルパス。**P.084「3-10」で `HTML要素.style` と書いたのと同じ要領で `mainImage.src` に代入**すれば完成です。
- **`forEach` への書き換え（7-8／p.288〜291）**：**`forEach()` は for とは違い、繰り返し条件や各繰り返し後の処理を指定する必要がなく、そのままループできる**ので **配列処理を効率よく、よりすっきり書ける**。書き方は **`配列.forEach((各配列の要素) => { … });`**。**慣習として配列には複数形、引数には単数形**（`animals` / `animal`）。**関数名を付ける場合はパラメーターに関数名を記述すればOK**。実際の書き換えは **for文をコメントアウトし、`thumbImages.forEach((thumbImage) => …)` にして同じ出力になるか確認してから中身を移植**。**`thumbImages[i]` と `thumbImage` で同じものが取得できている**わけです。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `querySelector()` / `querySelectorAll()` | 最初の1つだけ／条件に合うすべてを取得。複数扱うときは後者 |
| `NodeList` | `querySelectorAll()` の戻り値。`length` を持ちインデックスでアクセスできる |
| `mouseover` | マウスカーソルが要素に重なったときに発生するイベント |
| イベントオブジェクト（`event` / `e`） | コールバックに**自動的に渡される**イベント情報のオブジェクト |
| `event.target` / `event.target.src` | イベントを発生させたHTML要素／その src 属性の値 |
| `要素.src = 値` | HTML要素のsrc属性をJavaScriptから書き換える |
| `配列.forEach((要素) => …)` | 繰り返し条件の記述なしで配列を1つずつ処理する |
| 命名の慣習 | 配列は複数形（`thumbImages`）、引数は単数形（`thumbImage`） |
| `aspect-ratio` / `object-fit: cover` | 画像の縦横比を固定／はみ出す部分を切り取って枠を埋める |

**学んだ主な構文**

```js
// ===== 7-6 手順：取得 → for で展開 → mouseover → animate（p.281〜283） =====
const mainImage = document.querySelector('.gallery-image img');        // 1つだけ
const thumbImages = document.querySelectorAll('.gallery-thumbnails img'); // 複数
console.log(thumbImages);   // → NodeList(9) [img, img, …]  length: 9

for(let i = 0; i < thumbImages.length; i++) {
  thumbImages[i].addEventListener('mouseover', () => {
      mainImage.animate({opacity: [0, 1]}, 500);   // 0.5秒で 0 → 1
  });
}
```

```js
// ===== 7-7 完成形：event.target.src を mainImage.src に代入（p.287） =====
for(let i = 0; i < thumbImages.length; i++) {
  thumbImages[i].addEventListener('mouseover', (event) => {
      mainImage.src = event.target.src;            // 「mainImage」のsrc属性を操作
      mainImage.animate({opacity: [0, 1]}, 500);
  });
}
```

```js
// ===== 7-8 forEach の基本形と書き換え後の完成形（p.288・p.291） =====
配列名.forEach((各配列の要素) => {
  実行する内容
});

thumbImages.forEach((thumbImage)=>{               // 引数は単数形
  thumbImage.addEventListener('mouseover', (event) => {
    mainImage.src = event.target.src;
    mainImage.animate({opacity: [0, 1]}, 500);
  });
});
```

**できるようになったこと**：`querySelectorAll()` ＋ `length` ＋ `for` で複数要素にイベントを貼る書き方。**`event` → `event.target` → `event.target.src` とドットで掘り、`mainImage.src` に代入してHTML属性を書き換える**手順。`animate()` の第2引数に **数値だけを渡す簡略形（`, 500`）**。そして **for文を `forEach()` に安全に書き換える手順**（コメントアウト → 出力を照合 → 中身を移植）。

**つまずき・気づき**
- **`opacity: [0, 1]` は「消える」ではなく「一瞬消してから戻す」**。ローディングの `[1, 0]` と逆向きで、**同じプロパティでも配列の並びを変えるだけで演出の意味が真逆になる**。
- **`event.target` と `currentTarget` は別物**。コンソールのダンプで `currentTarget: null` に見えるのは仕様で、MDNは <cite index="63-1">currentTarget の値はハンドラー内でのみ利用でき、外では null になる</cite>と明記。確認したいときは `console.log(event.currentTarget)` と直接出す。
- **`event.target.src` がフルパスで出る**のも仕様どおり。MDNは <cite index="70-1">src プロパティは src HTML属性を反映し、ベースURIを含む完全なURLを保持する</cite>としている。属性の文字列そのものが欲しければ `getAttribute('src')`。
- **`thumbImages` は厳密には配列ではない**。MDNによれば <cite index="38-1">NodeList は Array ではないが forEach() で反復処理でき、Array.from() で本物の配列に変換できる</cite>。`map` や `filter` は使えない。
- **`for(let i …)` の `let` が効いている**。コールバック内で `thumbImages[i]` が正しく取れるのは **`let` が繰り返しごとに新しい `i` を作る**から。`var` だと全コールバックが最後の `i` を見てしまう。※教材にはない自分の補足。

### 7-9〜7-11｜スライドメニュー（`click`・共通オプション・`forEach` の index）（p.294〜310）

**何をしたか**
- **ねらい（7-9／p.294）**：**画面を広く使いたいときやモバイルで項目を省略したいときに活躍するのがスライドメニュー**。**これもこれまでに学習したイベントとアニメーションの組み合わせで実装できる**。動きは **右上のアイコンをクリックすると右端からメニューパネルが表示され、各メニューリストは上から順に右側からスッと表示されていく**。
- **HTMLとCSS（7-10／p.298〜301）**：**button 要素で開閉ボタンを設置し、開くボタンに `menu-open`、パネルに `menu-panel`、パネル内の閉じるボタンに `menu-close` という ID を割り振り**。アイコンはインラインSVG（`<title>メニューを開く</title>` 付き）。CSSでは **`position: fixed;` で位置を固定させる指定のほか、色や余白などの装飾**を加える。この時点ではパネルが画面右に出たままなので、**`translate` を追加して、Webページを開いた段階では画面の外側に配置して見えないようにしておきます**（`translate: 100vw;`）。
- **クリックで開閉（7-10／p.301〜303）**：`menuOpen` / `menuClose` / `menuPanel` を定数化し、まず **`console.log('メニューを開く')` でclickイベントが動くか確認**してからコメントアウト。**動かす内容は `translate`、値は開始時が画面外の `'100vw'`、終了時が `0`**。**動きの詳細は閉じるボタンと共通なので、定数 `menuOptions` を作ってまとめておきます**。閉じる側は **クリック対象が `menuClose` になっている点、開始時・終了時の値が逆になっている点だけが異なる**。
- **リストを1つずつ表示（7-11／p.304〜308）**：**`#menu-panel li` を `querySelectorAll()` で取得して `menuItems` に**。**P.288「7-8」を参考に `forEach()` で展開**すると5つの li が取れます。CSSで **`.menu-list li { opacity: 0; }` を加えて、何も操作していない状態では透明に**しておき、JS側で **`opacity: [0, 1]`（透明から不透明）と `translate: ['2rem', 0]`（少し右側から移動）** を指定。ただし **変化がわかりづらい**ので、**`forEach()` は関数の引数をカンマで区切ることで2つ目の引数にインデックスが代入される**ことを使い、**`delay: 300 * index`** で **P.234「6-11」と同じ要領で表示を少しずつずらす**。これで **上の要素から順に1つずつ表示**されます。
- **2回目のチラツキを直す（7-11／p.309〜310）**：**一度開いたメニューを閉じ、2回目に開くと挙動がおかしい**。**1回目の表示でメニューリストがすでに不透明になっているため、2回目ではすでに表示されていたテキストがパッと消え、再びふわっと表示されるようなチラツキ**が出ます。そこで **閉じるボタンをクリックしたときにメニューリストを元の透明に戻す指定**を追加。**これで2回目以降もちらつかず、スムーズに表示されます**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `translate: 100vw`（CSS） / `['100vw', 0]`（JS） | 画面外に待機させる初期状態／画面外→定位置へのスライドイン |
| `menuOptions` | `duration` / `easing` / `fill` をまとめた定数。開く・閉じるで使い回す |
| `forEach((要素, インデックス) => …)` | **引数をカンマで区切ると2つ目にインデックス（0始まり）が入る** |
| `delay: 300 * index` | インデックスに比例して遅延を増やし、上から順に表示させる |
| `opacity: 0`（CSS側） | JSでフェードインさせるための初期状態をCSSで用意しておく |
| `fill: 'forwards'` の副作用 | 終了状態が残るため、2回目の初期状態が1回目と変わってしまう |
| インラインSVG ＋ `<title>` | アイコンをHTMLに直接埋め込み、CSSの `fill` で色を変える／代替テキストの役割 |
| `max(32vw, 20rem)` | 「大きい方」を採用するCSS関数。狭い画面でも最低幅を確保できる |

**学んだ主な構文**

```css
/* ===== 7-10／7-11 css/style.css（p.301・p.305） ===== */
#menu-panel {
    position: fixed;
    top: 0;
    right: 0;
    z-index: 4;
    padding: 8rem 2rem 2rem;
    width: max(32vw, 20rem);
    height: 100vh;
    background-color: var(--brown);
    font-family: var(--oswald-font);
    translate: 100vw;            /* 追加。画面外（右）へ逃がす */
}
.menu-list li {
    margin: 1.5rem 0;
    opacity: 0;                  /* 追加。操作前は透明に */
}
```

```js
// ===== 7-9〜7-11 完成形（p.310／js/script.js） =====
const menuOpen = document.querySelector('#menu-open');
const menuClose = document.querySelector('#menu-close');
const menuPanel = document.querySelector('#menu-panel');
const menuItems = document.querySelectorAll('#menu-panel li');
const menuOptions = {              // 開く・閉じるで共通の詳細
  duration: 1400,
  easing: 'ease',
  fill: 'forwards',
};

// メニューを開く
menuOpen.addEventListener('click', () => {
  menuPanel.animate({translate: ['100vw', 0]}, menuOptions);

  // リンクをひとつずつ順に表示
  menuItems.forEach((menuItem, index) => {      // 第2引数で番号を受け取る
    menuItem.animate(
      {
        opacity: [0, 1],           // 透明から不透明に
        translate: ['2rem', 0],    // 少し右側から移動させる
      },
      {
        duration: 2400,
        delay: 300 * index,        // 0ms, 300ms, 600ms… とずらす
        easing: 'ease',
        fill: 'forwards',
      }
    );
  });
});

// メニューを閉じる
menuClose.addEventListener('click', () => {
  menuPanel.animate({translate: [0, '100vw']}, menuOptions);   // 値が逆
  menuItems.forEach((menuItem) => {
    menuItem.animate({opacity: [1, 0]}, menuOptions);          // 元の透明に戻す
  });
});
```

**できるようになったこと**：**CSSで画面外に逃がし、JSで戻す**という7-3と同じ型の再現。**共通のタイミング設定を定数に切り出して複数の `animate()` で使い回す**書き方。**`forEach()` の第2引数 `index` を `delay` の計算に使って順次表示を作る**テクニック。そして **`fill: 'forwards'` の残り状態が2回目の動作を壊す**ことに気づき、**閉じるときに初期状態へ戻して往復可能にする**設計。

**つまずき・気づき**
- **「2回目にチラつく」の原因が腑に落ちた**。`fill: 'forwards'` で閉じた後も li は `opacity: 1` のまま。次に開くと `[0, 1]` の最初のキーフレームで一瞬0に飛ぶので、**パッと消えて再表示される**ように見える。**アニメーションは状態を書き換える**と意識しないと踏む罠。
- **直し方が「アニメーションで戻す」なのが面白い**。閉じるときにも `animate({opacity: [1, 0]})` を流すことで、**消える動きの演出と次回の初期化を1つの指定で兼ねている**。
- **開くときは `index` を使い、閉じるときは使わない**という非対称は意図的。**現れるときは順番に、消えるときは一斉に**の方がストレスがない。※演出意図の解釈は自分の考察。
- **`delay: 300 * index` は掛け算1つで済む**。分岐や遅延値の配列を用意せず、**既にあるインデックスを計算に使う**のがスマート。4-16 の算術演算子がここで実務的に効く。
- **`menuOptions` に `delay` を含めていない**のは、li 側の `delay` が要素ごとに違って共通化できないから。**共通化できる部分とできない部分の線引き**がコードに現れている。

### 7-12〜7-15｜スクロールで要素を表示（Intersection Observer ＋ `forEach`）（p.314〜328）

**何をしたか**
- **ねらい（7-12／p.314）**：**スクロールに連動して要素が動くWebサイトはワクワクする動き**。**CHAPTER 6 で学んだ実装方法をより実践的に書いていく**。動きは **スクロールして要素が表示範囲内に入ると、少しぼやけて透明だった要素がふわっと浮かび上がるように表示される**。
- **クラスを付与する（7-13／p.318〜319）**：**HTMLの「ふわっ」と表示させたい要素に `fadein` というクラスを加える**。**見出しや文章、画像など、全部で17箇所に指定**しました。
- **Intersection Observer の設定（7-13／p.319〜321）**：**P.242「6-14」を振り返りながら基本設定**。まず **`animateFade` という関数を用意**（最初はコンソールに「ふわっ」と出すだけ）→ **定数 `fadeObserver` を作って `new IntersectionObserver(animateFade)` と記述**すると、**監視対象が画面に入ると animateFade を実行するよう指示できる**。監視対象は `querySelectorAll('.fadein')` で `fadeElements` に取得するが、**`fadeObserver.observe(fadeElements);` としたいところ、取得した複数の要素は配列なので `forEach()` で展開し、個別に監視するように指定する必要がある**。**ページを読み込んだときと、スクロールして要素が画面内に入ったときにコンソールに「ふわっ」が出力される**ようになります。
- **監視対象の情報を取得する（7-14／p.322〜323）**：**指定はP.247「6-15」と同じだが、今回は対象が複数あるので `forEach()` と組み合わせる**。**関数 `animateFade` の丸カッコに `entries` と書き加える。この `entries` の中に交差状態の情報が配列で渡される**ので、**`entries.forEach()` と書き、その丸カッコの中で監視対象のHTML要素を個別に `entry` という名前で受け取ります**。**画面に入っているかどうかを真偽値で判定する `isIntersecting`** は画面外なら `false`。**監視対象である要素を取得する `target` プロパティ**を使えば `entry.target` でHTML要素そのものが得られます。
- **交差しているときだけ実行する（7-14／p.324）**：**Intersection Observer はページを読み込んだ時点で用意した関数が実行される**。**今回は監視対象が画面に入ったときに実行されればいいので `isIntersecting` を利用**し、**`if (entry.isIntersecting)` を条件にする**ことで **`true` のときだけ中身が実行**されるようになります。これで **スクロールして画面内に入ったときにのみ反応**するようになりました。
- **アニメーションの指定（7-14／p.325〜326）**：**最初にCSSで `fadein` クラスを透明にしておく**（`.fadein{ opacity: 0; }`）。**コンソールへの指定はコメントアウトし、取得した要素 `entry.target` に `animate()` でアニメーションを指定**。**動かす内容は「透明から不透明にする」「ぼかしをなくす」「下から上に移動する」、動きの詳細は「2秒かけて動かす」「開始時と終了時は緩やかに変化させる」「最後のキーフレームの状態を保持する」**。これで **画面に入ったときにふわっと浮かぶ動きが完成**。ただし **スクロールするたびに何度も繰り返しアニメーションがあるのは少しわずらわしい**ので次節へ。
- **監視を停止する（7-15／p.327〜328）**：**交差するたびに関数が実行されるとブラウザーに負荷がかかる。また何度も動きがあるとユーザーが不快に感じることもある**ので、**一度表示されたあとは監視を止める**。**`animateFade` は第二引数に実行している `fadeObserver` を渡せる**。**混乱しないよう定数名を変え、慣例的に observer を短くした `obs` を使う**。**`unobserve()` メソッドの丸カッコには監視を止める要素 `entry.target` を記述**。**POINT：`unobserve()` は `fadeObserver.observe(fadeElement);` の逆の意味**。結果、**ページ下部までスクロールしたあと上部に戻ってもアニメーションは発動しなくなり、監視が停止していることがわかります**。**シンプルなプログラムなら違いは出にくいが、`animateFade` を複数の Intersection Observer で利用する場合にどこから呼び出されたかわからなくなることがあるため、第二引数でどの observer を呼び出すのかを指定します**。締めは「**見た目だけでなく、効率の良い書き方やブラウザーへの負荷についても考えながらプログラムを書けるようになっていくといい**」。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `new IntersectionObserver(関数名)` | 監視オブジェクトを作る。カッコの中に「画面に入ったら実行する関数」を渡す |
| `observer.observe(要素)` / `unobserve(要素)` | 監視を開始する（**1回につき1要素**）／監視をやめる |
| `entries`（第1引数） | 交差状態が変化した要素の情報が入った配列 |
| `obs`（第2引数） | 監視オブジェクト本体。慣例的に observer を短くした名前。中から `unobserve()` を呼べる |
| `entry.isIntersecting` | その要素が画面内に入っているかを表す真偽値 |
| `entry.target` | 交差状態が変化した**HTML要素そのもの**。`animate()` の対象になる |
| `.fadein` クラス | ふわっと表示させたい要素の目印。今回は17箇所に付与 |
| `filter: blur()` | ぼかしの量。`blur(.4rem)` → `blur(0)` でピントが合う演出になる |

**学んだ主な構文**

```js
// ===== 7-13 手順：関数 → 監視設定 → forEach で1つずつ登録（p.319〜321） =====
const animateFade = () => {
  console.log('ふわっ');
};
const fadeObserver = new IntersectionObserver(animateFade);

const fadeElements = document.querySelectorAll('.fadein');
// fadeObserver.observe(fadeElements);   ← 配列は渡せないのでNG
fadeElements.forEach((fadeElement) => {
  fadeObserver.observe(fadeElement);     // 1つずつ監視に登録する
});
```

```js
// ===== 7-14 手順：entries → entry → isIntersecting で絞る（p.322〜324） =====
const animateFade = (entries) => {
  entries.forEach((entry) => {
    if (entry.isIntersecting) {          // 画面内に入っているときだけ
      console.log(entry.target);
    }
  });
};
```

```js
// ===== 7-12〜7-15 完成形（p.315〜316・p.327〜328／js/script.js） =====
/*
スクロールで要素を表示
================================================ */
// 監視対象が範囲内に現れたら実行する動作
const animateFade = (entries, obs) => {        // 第2引数で observer 自身を受け取る
  entries.forEach((entry) => {
    if (entry.isIntersecting) {
      entry.target.animate(
        {
          opacity: [0, 1],
          filter: ['blur(.4rem)', 'blur(0)'],   // ぼけ → クリア
          translate: ['0 4rem', 0],             // 下から浮き上がる
        },
        {
          duration: 2000,
          easing: 'ease',
          fill: 'forwards',
        }
      );
      // 一度ふわっと表示されたら監視をやめる
      obs.unobserve(entry.target);
    }
  });
};

// 監視設定
const fadeObserver = new IntersectionObserver(animateFade);

// .fadeinを監視するよう指示
const fadeElements = document.querySelectorAll('.fadein');
fadeElements.forEach((fadeElement) => {
  fadeObserver.observe(fadeElement);
});
```

```css
/* ===== 7-12／7-14 css/style.css（p.316・p.325） ===== */
.fadein{
    opacity: 0;      /* 初期状態は透明。JS側で [0, 1] に */
}
```

**できるようになったこと**：**「フックになるクラス（`.fadein`）をHTML側にばら撒き、JSはそれを全部拾って一律に処理する」**という、要素が増えてもコードが増えない設計。`new IntersectionObserver(関数)` → `querySelectorAll()` → `forEach` で `observe()` という3ステップの型。コールバックの `(entries, obs)` から **`entry.isIntersecting` で判定 → `entry.target` に `animate()` → `obs.unobserve()` で後始末**まで一続きで書けること。`opacity` / `filter` / `translate` を1つの `animate()` にまとめる書き方。

**つまずき・気づき**
- **`observe()` に配列を渡せない**のがこの節の山場。MDNによれば <cite index="86-1">observe() は監視対象の集合に「1つの要素」を追加するメソッドで、引数は targetElement（単数）</cite>。**1つの監視オブジェクトで複数要素を見られるが、登録は1つずつ**なので `forEach` が必須。7-8 で `forEach` を学んだ意味がここで回収される。
- **読み込んだ瞬間に「ふわっ」が出るのは仕様どおり**。MDNは <cite index="86-1">observe() が呼ばれた後の最初のレンダリングサイクルで、対象がビューポートに対してまだ動いていなくてもコールバックは必ず発火する</cite>と明記。**だから `if (entry.isIntersecting)` の判定が必須**で、これがないと画面外の要素まで即座にアニメーションしてしまう。
- **`obs.unobserve(entry.target)` は演出と性能の両取り**。MDNは <cite index="87-1">unobserve() は指定した対象要素の監視を停止する</cite>とし、仕様も <cite index="82-1">unobserve() は遅延読み込みのユースケースに対応するもので、対象が可視になった後は追跡し続ける必要がないため</cite>と説明している。教材の「ブラウザーへの負荷」という言い方と一致する。
- **第2引数 `obs` を使う設計が良い**。MDNは <cite index="81-1">コールバックは IntersectionObserverEntry のリストとオブザーバー自身を受け取る</cite>としている。外側の `fadeObserver` を直接参照してもいいが、**引数で受ければ関数が単体で完結する**ので、教材の言う「複数の observer から使い回す」場面で効く。
- **`forEach` が2回登場する**が意味は別物。`entries.forEach` は **「今回変化した要素たち」**、`fadeElements.forEach` は **「監視に登録する要素たち」**のループ。
- **`.fadein { opacity: 0; }` の1行がCSSの全て**。7-3のローディング、7-11のメニューリストと同じで、**「JSが動く前の初期状態はCSSに書く」**が3回連続で出てきた。この章を通した一番大きな型。
- **17箇所すべてに手でクラスを付けている**のも重要。**JSでセレクタを複雑にせず、HTML側に目印を置いてJSを単純に保つ**分担なので、対象を増やすときも `class="fadein"` を足すだけで済む。※設計の解釈は自分の考察。

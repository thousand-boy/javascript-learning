**何をしたか（読んで理解したこと）**
- **1-1 JavaScriptとは**：JavaScriptは **Webページに機能を追加できるプログラミング言語** で、**ブラウザーで動く言語として1995年に誕生** したと学びました。今やJavaScriptを使っていないWebサイトを見つけるのが難しいほど普及しています。Webサイトは「コンテンツを表示する文書構造のための **HTML**」「見た目を変化させる **CSS**」「動作部分を作る **JavaScript**」の3つで成り立ちます。**車の例え**：骨組み＝HTML／色などの見た目＝CSS／アクセル・ブレーキ・ライトなどの機能面＝JavaScript。
- **1-1（続き）HTML・CSSだけではできないことを実装するのがJavaScript**：HTML・CSSだけでもWebサイトは作れ、CSSでアニメーションや画面幅対応も可能。ただし **HTML・CSSは一度ブラウザーに読み込まれると最初のコードから変化しない**。JavaScriptは **HTML・CSSをリアルタイムで書き換えたり、ユーザーの操作にあわせて動きや機能を加えられる** ため、より高度で豊かな表現ができます。
- **1-1（続き）初心者にもおすすめ／JavaとJavaScriptは別物**：JavaScriptはブラウザーで動くので特別な装置・環境が不要。人気言語ゆえ情報・学習サイト・コミュニティも豊富で始めやすい。**コラム**では「Java」と「JavaScript」が別言語であることを解説。JavaScriptは Netscape社が開発したブラウザー向け言語で **当初は Mocha（モカ）→ LiveScript（ライブスクリプト）→ JavaScript** と改名（当時注目されていた Sun Microsystems社〈現：オラクル社〉の「Java」にあやかった命名）。両者は「メロンとメロンパン」の関係でよく例えられ、名前と“プログラミング言語である”点しか共通せず、書き方も用途も別物。
- **1-2 JavaScriptでできること①：条件によってHTMLやCSSを書き換える**：JavaScriptの指示でHTML・CSSを操作し表示を変更できる。書き換えは実行と同時にブラウザーへ反映され、**ページ全体を再読み込みせず、指定した部分だけ変更** されるので体感速度が速い。具体例として——
  - **テキストの書き換え**：「メニュー」→クリックで「閉じる」、「読み込み中…」→完了で「完了！」など。
  - **画像の変更**：`<img src="ファイル名.jpg" alt="">` の **`src` の値だけを書き換えて別画像に差し替え**（例：`cat.jpg`→`dog.jpg` で猫→犬）。
  - **色の変更**：CSSの文字色・背景色もJavaScriptで変更でき、**ダークモード切り替え** などに利用（ダークモードの詳細は本書 P.102 で解説とのこと）。
- **1-2（続き）JavaScriptでできること②：ユーザーのアクションに応じた動きを付ける**：CSSアニメーションは読み込み時点で内容・タイミングが固定されるが、JavaScriptは **クリックやスクロールなどユーザーの操作にあわせて動きを決められる**。
  - **スクロールで要素を表示**：スクロールに合わせて画像やテキストが横・下からスッと現れる演出。
  - **フォームバリデーション**：入力フォームの内容が要件を満たすかをチェックする仕組み。必須項目が空だと「必須項目です」等のメッセージを表示。
- **1-3 様々なJavaScriptを使ったWebサイト（実例4サイト）**：普段意識しないだけで、身近なサイトの色々な場面でJavaScriptが使われていることを、実サイトのキャプチャで確認しました（下表参照）。ローディング演出、数字→文字への変換見出し、ページ遷移アニメ、絞り込み検索、カルーセル、Googleマップ連動、背景ぼかし、言語選択、ふんわり表示、スライドメニュー、スクロール連動、動く波、画像切り替え、流体シェイプ、タイプ診断など。

**読んで理解したこと（この回のまとめ）**：JavaScriptが「Webページに機能を足す、ブラウザーで動く言語（1995年誕生）」であること。Webサイトが HTML／CSS／JavaScript の3層で成り立ち、JavaScriptだけが **読み込み後もリアルタイムに書き換え・操作できる** という決定的な違いを持つこと。JavaScriptでできる代表例（テキスト書き換え・画像差し替え・色変更／ダークモード・スクロール表示・フォームバリデーション）。そして実在の4サイト（ACES／ShiobaLove／Sustainable PRODUCTS／snaq.me）で、ローディング・カルーセル・地図連動・言語切替・スクロール連動・タイプ診断などが実際に使われていること。Java と JavaScript が別言語である点も整理できました。

**つまずき・気づき**
- HTML・CSS本を終えて最初の疑問だった「HTML・CSSで動きも付けられるのに、なぜJavaScriptが要るのか？」の答えは、**「HTML・CSSは読み込み後は固定。ユーザー操作に応じてリアルタイムに書き換えられるのがJavaScript」** という点だった。役割の線引きがはっきりした。
- 画像の差し替えは「新しい `<img>` を作る」のではなく **`src` 属性の値だけを書き換える** という発想。CSSのプロパティ変更（色など）も同じで、**“既にある要素の一部を書き換える”** のがJavaScriptの基本動作のイメージだと掴めた。
- 「JavaScript ≠ Java」は初学者が最初に混同しやすいポイント。**Mocha→LiveScript→JavaScript** という改名の経緯と、Javaにあやかった命名だったという背景を知ると腹落ちする。
- 1-3の実例は「言われてみればJavaScript」というものばかり（カルーセル、絞り込み、地図連動、言語切替…）。**普段使っているサイトの“動き”を意識して観察する** と、これから学ぶ内容のゴールが具体的にイメージできる。

### 2026-07-16〜19（続き）｜第2章 JavaScriptに触れてみよう！ 2-1〜2-5（書く場所／VSCode環境／初コード／基本ルール／コンソール）

> ※ここから章タブは「Getting Started」。第2章は概念中心の第1章と違い、**実際にコードを書いて動かす** 実践パートです。サンプルデータは `chapter2/03-demo1`・`chapter2/03-demo2`・`chapter2/05-demo`（QRコード／ダウンロード提供）。

**何をしたか**
- **2-1 JavaScriptはどこに書く？**：Webページに適用する方法は大きく2通り。①**HTMLファイルの中に直接書く**（必ず `<script>〜</script>` の間に記述。範囲外に書くとJavaScriptと認識されず動かない）。記述場所は `<head>` 内でも `<body>` 内でも位置は自由。②**外部の `.js` ファイルを作って読み込む**。①は同じJSを複数ページで使う場合に全HTMLへ同じコードを書く必要があり非効率なので、複数ページで使うなら②が良い、と学びました。
- **2-1（続き）外部ファイルの読み込み方**：拡張子 `.js` のファイルを作り（**中に `<script>` タグは不要**、直接コードを書く）、HTML側から `<script src="js/hello.js"></script>` のように **`src` 属性で指定して読み込む**。読み込み位置も `<head>`／`<body>` 内どこでも可。修正時は1つの `.js` を直すだけで済む利点あり。**複数ファイルの読み込みも可能** で、`<script>` を並べた順（例：`hello.js`→`bye.js`→`goodnight.js`）に読み込まれ処理が実行されます。
- **2-1（続き）コラム：オンラインツール CodePen**：ブラウザー上でHTML／CSS／JavaScriptを書いて表示確認できるWebサービス。会員登録なしでも記述・動作確認ができる。本書デモでも使用（左上の［Start Coding］でコード画面へ。HTML欄は基本 `<body>` 内の部分のみ記述すればOK。外部ライブラリー読み込みや画像素材も無料。有料版は非公開・共同作業も可）。https://codepen.io/
- **2-2 JavaScriptを書く環境を用意しよう**：JSは特殊な開発環境不要で、HTML／CSSと同じツールで書け、表示確認もWebブラウザーで行える。本書は **エディター** として Microsoft 製の **Visual Studio Code（VSCode）** を採用（初期状態でも必要機能が揃い初心者向き、Mac・Windows とも無料）。公式サイト（https://code.visualstudio.com/ ）からダウンロードしてインストール。※インストール手順は著者のYouTube動画（https://www.youtube.com/watch?v=kdl6sGzmK5Q ）でも紹介。
- **2-2（続き）VSCodeを日本語化する／その他のエディター**：初期はメニューが英語。左側メニュー最下部の拡張機能アイコン →検索ボックスに「Japanese」と入力 → **[Japanese Language Pack for Visual Studio Code]** を［Install］→ **VSCode を再起動** で日本語化。コラムでは他エディター（DreamWeaver／WebStorm／Sublime Text）も料金付きで紹介（※料金は変動あり。下表参照）。
- **2-3 はじめてのJavaScriptを書いてみよう ①HTML内に書く方法**：VSCode を起動 → ［フォルダーを開く］で保存場所を選び新規フォルダー **「03-demo1」** を作成（※［フォルダーを開く］が無ければ上部メニュー［ファイル］→［開く…］）。フォルダー内で **［＋］新規ファイル作成アイコン** から **`index.html`** を作成（上部メニュー［ファイル］→［新規ファイル］でも可）。※Web からダウンロードしたファイルで「作成者を信頼しますか？」が出たら「はい、作成者を信頼します」を選ぶ。
- **2-3（続き）初コードを書いて動かす**：`index.html` にベースHTMLを用意し、`<body>` 内に `<script></script>` を記述。開始・終了タグの間に **`window.alert('はじめてのJavaScript!');`** と記述（**`'はじめてのJavaScript!'` 以外はすべて半角英字**）。保存（Mac は ⌘+S／Windows は Ctrl+S）して `index.html` をダブルクリックしブラウザー表示すると、**警告ダイアログ** が表示され、初コードが動作。`window.alert` は「カッコやシングルクォーテーションで囲まれた中のテキストを警告ダイアログとして表示する」コード。
- **2-3（続き）②JavaScriptファイルを作成する方法**：新規フォルダー **「03-demo2」** を作り、その中に **`first.js`** を作成し `window.alert('はじめてのJavaScript!');` を記述して保存。同フォルダーに `index.html`（①の `alert` 部分を消したベース）を作り、`<body>` 内に `<script></script>` を用意 → **開始タグに `src="first.js"` を書き足す**（`<script src="first.js"></script>`）ことで `first.js` を読み込ませる。ブラウザー表示すると①と同様に警告ダイアログが出ました。※うまくいかない時は P.337「8-2 よくあるエラー一覧」でスペルミス・全角混入を確認。
- **2-3（続き）`window.` は省略できる**：`window.alert(…)` の **`window.` は省略可能**。`alert('はじめてのJavaScript!');` と書いても同じく動作する（詳細は 2-4）。
- **2-4 JavaScriptを書くときの基本ルール（基本文法）**：`window.alert('はじめてのJavaScript!');` は **「オブジェクト . メソッド('パラメーター')」** の3パーツ構成。**オブジェクト（物）**＝動作させる対象。ここでは `window`＝ブラウザーのウィンドウそのもの（警告は画面全体に出るため対象が window）。オブジェクトには `window` の他 `history`（閲覧履歴）・`document`（HTML全体）・`location`（アドレス情報）・`console`（コンソール）などが階層的に存在（詳細は P.063「3-5 DOMを理解しよう」）。
- **2-4（続き）メソッドとパラメーター**：**メソッド（動作・命令）**＝英語 method＝「方法」。`alert()`＝「警告ダイアログを表示する」動き。`alert()` は **組み込みオブジェクト（ビルトインオブジェクト）** としてブラウザーに最初から用意されたプログラムの一部（文字列操作や数学計算ができる組み込みオブジェクトもあり、CHAPTER 3 で紹介）。**パラメーター（調整値）**＝メソッドを補足する情報で、丸カッコ内に記述。これで表示メッセージが決まる。**通常のテキストのパラメーターは引用符（シングル or ダブルクォーテーション）で囲む** 必要がある。まとめると基本文法は `オブジェクト.メソッド('パラメーター')`＝「windowに対して『はじめてのJavaScript!という警告を出してね』」という具体的な指示。
- **2-4（続き）コードを書くときのルール**：①**半角英数字で書く**（記号含め全て半角。全角スペースもエラー）。②**大文字・小文字は区別される**（`alert` を `Alert` と書くとエラー）。③**文字列は引用符で囲む**（本書はシングルクォーテーション。理由＝HTML属性値のダブルと区別／US配列でシフト不要／見た目がシンプル。どちらでも可）。④**命令文の最後に `;`（セミコロン）を付ける**（命令文の区切り。日本語の句点「。」に相当。省略でも動くことが多いが、判別しづらいので最初は必ず付ける）。
- **2-4（続き）コラム：特殊文字を表示させる（エスケープ表記）**：文字列中に引用符自体を含めたい時（例 `You're special!`）、`alert('You're special!');` だとどこまでがパラメーターか判別できずエラー。**`\`（バックスラッシュ）／`¥`（円マーク）を文字と組み合わせる** ことで回避＝`alert('You\'re special!');`。この `\`／`¥` 自体は表示されない。この書き方を **エスケープ表記／エスケープシーケンス** と呼ぶ（`\'`＝'、`\"`＝"、`\n`＝改行 など。詳細は MDN）。
- **2-5 コンソールを使ってみよう**：Google Chrome 標準搭載の **デベロッパーツール** の中にある **コンソール** で、JSが正しく動いているか検証できる。表示は Chrome で Web ページを開き **［右クリック］→［検証］**（ショートカット：Mac は Shift+⌘+C／Option+⌘+I、Windows は Ctrl+Shift+I／F12）。開いたら **[Console] タブ** をクリックするとコンソールが表示され、`>` アイコンのある部分に直接JSを入力・実行できる。
- **2-5（続き）コンソールを使ってみる**：コンソールに `alert('はじめてのコンソール！');` と入力し Enter/return で警告ダイアログ表示。次に **`console.log('はじめてのコンソール！');`** を入力すると、次の行に「はじめてのコンソール！」が **出力** される。構成は `console`（オブジェクト）+ `log()`（メソッド）+ パラメーター。`log`＝「記録する／出力する」。この `console.log()` はコンソール以外（HTMLの `<script>` 内）に書いても同様に動作し、保存してファイルを開くとデベロッパーツールのコンソールに出力される。
- **2-5（続き）なんのためにコンソールを使うのか**：主に2つ。①**エラーの確認**＝入力ミスがあると赤字でエラーメッセージが表示される（例：閉じ引用符の書き忘れで `Uncaught SyntaxError: Invalid or unexpected token`）。間違った場所・原因の特定に不可欠（エラー一覧は P.333「CHAPTER 8 エラーと解決方法」）。②**制作途中のプログラムの確認**＝`console.log()` でその時点のデータを出力し、意図通りデータが渡っているか検証できる。想定と違えば、その `console.log()` より前に間違いがあるとわかる。少しずつ確認しながら書く方が結果的に実装時間が短縮。`alert()` と違い警告ダイアログが出ないので毎回OKを押す手間が省け、細かいデータ確認も可能。

**つまずき・気づき**
- JSの置き場所は「HTML直書き」と「外部 `.js`」の2択。**複数ページで同じ処理を使うなら外部ファイル一択**（修正が1ファイルで済む）。この判断基準は、HTML/CSS本でCSSを外部ファイル化したのと同じ考え方。
- `window.alert` の **`window.` を省略できる** のは、`window` が特別扱いのオブジェクトだから。ただし `console.log` の `console` は省略できない——省略できるのは `window` に限る、という点を混同しないよう注意。
- **基本文法 `オブジェクト.メソッド('パラメーター')` は今後ずっと使う型**。今は `window.alert` と `console.log` の2例だけだが、この「対象.動作(補足情報)」の形で読み解くクセをつけると、後の章のコードも分解して理解できそう。
- エラーで焦らないための保険が **セミコロンを必ず付ける／半角で書く／大文字小文字を合わせる** の3点。特に **全角スペースの混入** は見た目で気づきにくく、`Uncaught SyntaxError` の典型原因。困ったらまずコンソールの赤いエラーを読む。
- `alert()` と `console.log()` の使い分け：動作の合図なら `alert()`、**開発中のデータ確認は `console.log()`**（ダイアログのOK押下が不要で、細かい値も見られる）。デバッグの基本姿勢として「最後まで書いてから確認」より「少しずつ `console.log()` で確認」の方が速い、という指摘が実践的。

**この章で作るもの（3-1 完成形の把握）**

**何をしたか（3-2 必要なファイルを用意しよう）**
- **フォルダー／ファイルの用意**：任意の場所に **「ColorPicker」** フォルダーを作成し、その中に **`index.html`** を作成。カラーピッカー本体は `<input>` タグの **`type` 属性を `color` にする** だけで表示できる（＝色を選択できる入力欄）。※HTMLやCSSは本書がサンプル提供しており、JavaScriptの学習に専念できるようになっている。

- **CSSファイルの用意**：「ColorPicker」内に **「css」フォルダー** を作り、その中に **`style.css`** を作成（ベースの色・余白・配置を指定）。この `style.css` を `index.html` の `<head>` 内に **`<link>` タグで読み込ませる**。保存してブラウザーで確認すると、**背景色が黒**になり、カラーピッカーを含む要素（白いカード）が画面中央に表示される。これでCSSの設定は完了。
- **JavaScriptファイルの用意**：同じく「ColorPicker」内に **「js」フォルダー** を作り、その中に **`script.js`** を作成。現段階では読み込み確認のため **`console.log('準備完了！');`** だけを記述。これを `index.html` に読み込ませるが、ここでは **`<head>` 内に**、かつ **`src` 属性に加えて `defer` 属性も一緒に** 記述する（`<script src="js/script.js" defer></script>`）。ファイルを保存してコンソールを見て **「準備完了！」** と表示されれば、JSファイルが正しく読み込まれている証拠。
- **3-2 コラム：なぜ defer 属性を付けたのか？**：`defer` を付ける理由は簡単に言えば **Webページの読み込みを速くするため**。ブラウザーはHTMLを上から下へ順番に解析・実行する。`<script>` に `defer` があると、**1つの処理の終了を待たずに次を行う「非同期処理」** で進められる。3パターンを図で比較——
  - **① `<head>` 内でJSを読み込む（deferなし）**：`<script>` に到達した時点で **HTMLの解析が一旦停止**し、JSの読み込み・実行が行われ、その後に残りのHTML解析が続く。JSがHTML要素に紐付いている場合、要素がまだ無く **実行できずエラーになることもある**。
  - **② `</body>` の直前で読み込む（従来の推奨）**：HTMLの解析が終わった段階でJSを読み込み・実行するので、HTML要素と紐付いたプログラムも問題なく処理される。ただし **Webページ全体の読み込み時間が短縮されたわけではない**。
  - **③ `<head>` 内で `defer` を付けて読み込む（本書の推奨）**：`<script>` に `defer` を指定すると **HTMLの解析を中断せず、JSファイルの読み込みが（解析と）同時に行われる**。そして **HTMLの解析が終了したあとにJSが実行される** ので、Webページの読み込み速度も改善される。→ **基本は「`<head>` 内で `defer` を付けて読み込む」** のがよい。
  - **非同期処理のたとえ**：コンビニのレジでお弁当を温めてもらう場面。店員はお弁当を温めている間に会計をし、温め終わったら袋に入れて渡してくれる＝これが非同期処理。非同期でないと、温め終わるまでレジ前でただ待つ無駄な時間が発生する。
- **3-2 ディレクトリー構成**：現段階のフォルダー構成は以下の通り（次節から `script.js` に本格的にコードを書いていく）。
  ```

  ├── index.html
  ├── js/
  │    └── script.js
  └── css/
       └── style.css

**何をしたか（3-3 カラーピッカーの色の値を取得しよう）**
- **HTML要素の取得方法**：JavaScriptから扱いたいのは、ID が **`colorPicker`** の `<input>` タグ。このIDを元にJavaScriptと紐付ける。HTMLの中から任意のIDが付いた要素を取得するには **`querySelector()` メソッド** を使う。基本文法 `オブジェクト.メソッド('パラメーター')`（2-4で学習）の通り、3パーツで構成される。
  - 記述例：`document.querySelector('セレクター')`
  - 意味：「**HTML全体を表す `document` オブジェクト** の中から、**指定したセレクター（＝パラメーター）** を持つ要素を **取得してね（＝メソッド `querySelector()`）**」。
  - **セレクターの書き方はCSSと同じ**。ID名を指定するなら `#ID名`、クラス名なら `.クラス名`。
- **実際に書いてみる**：前節の `console.log('準備完了！');` を元に、パラメーターを `'準備完了！'` から **`document.querySelector('#colorPicker')`** に書き換える。※オブジェクトやメソッドは文字列ではないので、`console.log()` のカッコの中を **シングルクォーテーションで囲む必要はない**。保存してコンソールに **`<input id="colorPicker" type="color">`** と表示されれば、無事に要素を取得できている。
  - **POINT**：JavaScriptは大文字・小文字・スペースなど1文字でも間違いがあると動作しない。**`querySelector` の「S」は大文字** になっている点に注意。
- **3-3 もし null と表示されたら？**：コンソールで確認すると **`null`** と表示されることもある。`null` は「何もない」を表す言葉で、ここでは「**そんなIDないよ**」の意味。例として `'#colorpicker'`（picker が小文字）と書くと `null` になる。正しいID名は **`colorPicker`**（P が大文字）。正しく書いたつもりでもエラー（`null`）になったら、**スペルや大文字・小文字にミスがないかチェック** する。
- **3-3 値を取得する**：実際に取得したいのは **カラーピッカーのタグそのものではなく、その値であるカラーコード**。値は **取得した要素の最後に `.value` を繋げるだけ** で取得できる。
  - `console.log(document.querySelector('#colorPicker').value);`
  - 保存してコンソールを見ると、カラーコードが表示される（現時点ではデフォルトの黒 **`#000000`**）。※現段階では別の色を選んでも `#000000` から変化しない。これは**まだ変化に対応させるための指示（イベント）をしていないから**（→ 後の節で対応）。
  - **補足（value属性）**：HTMLファイル内で `<input>` 要素に **`value` 属性が指定されている場合は、それが値としてコンソールに表示される**。試しに `<input id="colorPicker" type="color" value="#00bbdd">` と色の初期値を指定すると、コンソールに **`#00bbdd`** と表示される。※今回はデフォルトの黒で進めるので、試しに書いた `value="#00bbdd"` は削除して元に戻しておく。

**何をしたか（3-4 テキストを変更しよう）**
- **JavaScriptから文字を表示させる方法**：HTMLは単純に文字を入力すればその場所に表示されるが、JavaScriptでは **どこに・どんなテキストを表示させたいのかを明確に指示する必要がある**。考え方としては「新たにテキストを加える」というより **「今表示させているテキストを書き換える」** に近い。
- **「どこの」「何を」「どう変えたいのか」を3本立てで指定**（今回の実装内容）：
  - **① 「カラーコードを検索」と書かれている部分の**
  - **② テキストを**
  - **③ 「カラーコード：」に変える**
- **① 「どこの」を指定する**：「カラーコードを検索」と表示されているのは、HTMLの **`colorText` というIDが付いた `<p>` タグ**。前節同様 `document` オブジェクトと `querySelector()` メソッドでID名 `colorText` を指定する。
  - `document.querySelector('#colorText')` → これで「どこの」の指定が完了。
- **② 「何を」を指定する**：「テキストを変えたい」は **`textContent` を、ピリオド `.` で繋げる** ことで指定できる。**「C」のみ大文字**になる点に注意（`textContent`）。
  - `document.querySelector('#colorText').textContent`
- **③ 「どう変えたいのか」を指定する**：`textContent` のあとに **イコール `=`** を書き、変更したいテキストを **シングルクォーテーション `'` で囲んで** 指定。行の最後に **セミコロン `;`** を付けて完了。
  - `document.querySelector('#colorText').textContent = 'カラーコード：';`
  - 保存すると、「カラーコードを検索」と書いてあった部分が **「カラーコード：」** に書き換えられる。
- **`=` の意味（重要）**：算数・数学では `=` は「等しい値」だが、**JavaScriptでは `=` は「代入する」という意味**。`=` より右側のものを、`=` より左側のものに入れておく＝「置き換える」ということ。
  - つまり `document.querySelector('#colorText').textContent = 'カラーコード：';` は「HTMLページ（`document`）から `colorText` というIDの要素を探し出し、その **要素内のテキスト（`textContent`）** に **文字列『カラーコード：』を代入する**」という指示。
- **3-4 HTMLタグは無視される**：`textContent` で変更できるのは **純粋に文字列の部分のみ**。HTMLのタグを含めても、**タグも文字列として（そのまま）表示される**。
  - 例：`document.querySelector('#colorText').textContent = '<h1>カラーコード：</h1>';` と書くと、`<h1>` タグごとWebページ上に文字として表示されてしまう。タグは表示させたくないので元に戻す。
  - **POINT**：**HTMLタグも含めたいなら `textContent` の代わりに `innerHTML` が使える**。今回の例なら `document.querySelector('#colorText').innerHTML = '<h1>カラーコード：</h1>';` と記述すれば、「カラーコード：」を `<h1>` タグを使って（見出しとして）表示できる。

**何をしたか（3-5 DOMを理解しよう）**
- **DOMとは？**：ブラウザーがHTMLを読み込むと、内部では **データ構造** が作成され、その内容に応じてページが描画される。このデータ構造のことを **DOM（ドム）** と言う。DOMは **「Document Object Model（ドキュメントオブジェクトモデル）」** の略で、**HTMLを組織図のようなツリー状に分解し、HTMLとJavaScriptのようなプログラミング言語を接続している**。
  - 流れ：**HTML → DOM → Webページ**。例えば `<body><h1>こんにちは！</h1><button>OK</button></body>` というHTMLは、DOM上で body 配下に h1・button がぶら下がるツリーになり、それを元にWebページ（「こんにちは！」と「OK」ボタン）が描画される。
  - **たとえ**：DOMは料理のレシピと、完成したプリンの間にある「成り立ちをまとめた構造図」に似ている（プリン＝カスタード＋カラメル、カラメル＝さとう＋水…とツリー状に分解できる）。
- **DOMは操作できる**：DOMは **JavaScriptでWebページ上の表示を操作するために存在** する。前節（3-4）でテキストを書き換えたのは、**HTMLファイルそのものを書き換えたのではなく、その間にあるDOMを操作していた**。テキスト変更だけでなく、**要素やスタイルを追加・削除する** ことも可能。
- **DOMのツリー構造（DOMツリー）**：DOMではHTML文書を階層構造で表現する。この階層構造を **DOMツリー** と呼ぶ。文書を1本の木に見立てて枝分かれする様を表している。DOMツリーのそれぞれの枝は **ノード** で構成される。**ノード**＝日本語で「節」や「結び目」。HTMLでタグやエレメントなどと呼ばれる **各要素そのもの** のことで、このノードにJavaScriptからアクセスして操作している。
  - 一番上にくるノードは **`document` ノード**。その下にHTMLファイルに記述されているような階層でつながる（document → doctype／html → head・body → …）。
- **ノードの種類**：ノードにはいくつかの種類があり、主に以下に分類される。

| ノードの種類 | 例 |
|---|---|
| 要素ノード | `<p id="colorText">カラーコードを検索</p>` |
| 属性ノード | `id="colorText"` |
| テキストノード | カラーコードを検索 |

- **ノードの親子関係**：ノード同士の位置関係には **「親子」や「兄弟」** などの用語を使うことがある。例えば `<body>` の階層から見ると——
  - **親ノード**：すぐ上の階層にある `<html>`
  - **子ノード**：すぐ下にある `<div>`
  - **兄弟ノード**：同じ階層にある `<head>`
  - DOM操作を行ううえで、こうした階層関係を使う場合もあるので覚えておくとよい。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| カラーピッカー | `<input type="color">` で表示できる、色を選択できる入力欄（本章で作るアプリ） |
| `<input type="color">` | type属性を color にすることでカラーピッカー（色選択の入力欄）を表示する |
| `defer` 属性 | `<script>` に付ける属性。HTML解析を止めずにJSを同時読み込みし、解析終了後にJSを実行する。ページ読み込みが速くなる |
| 非同期処理 | 1つの処理の終了を待たずに次の処理を進める方式（コンビニでお弁当を温めつつ会計するイメージ） |
| `document` オブジェクト | HTML全体（ページ）を表すオブジェクト。要素取得の起点になる |
| `querySelector()` | HTMLから指定したセレクターの要素を取得するメソッド。「S」が大文字な点に注意 |
| セレクター | 取得対象の指定方法。CSSと同じ書き方（ID＝`#ID名`／クラス＝`.クラス名`） |
| `.value` | 取得した入力要素の「値」を取り出すプロパティ。カラーピッカーではカラーコードが得られる |
| `null` | 「何もない」を表す値。`querySelector()` で該当IDが無いと返る（＝「そんなIDないよ」） |
| `value` 属性（input） | HTML側で入力欄の初期値を指定する属性。指定するとその値が取得される |
| `textContent` | 要素内のテキストを取得・変更するプロパティ。HTMLタグは文字列として扱われる（Cのみ大文字） |
| `innerHTML` | 要素内をHTMLタグごと変更できるプロパティ。タグが有効な要素として反映される |
| `=`（代入） | JavaScriptの `=` は「等しい」ではなく「右の値を左に代入（置き換え）する」意味 |
| DOM（Document Object Model） | ブラウザーがHTMLから作る内部データ構造。HTMLをツリー状に分解しJSと接続する |
| DOMツリー | DOMがHTML文書を1本の木に見立てて階層表現したもの |
| ノード | DOMツリーを構成する各要素（節・結び目）。JSからアクセスして操作する |
| 要素ノード／属性ノード／テキストノード | ノードの主な種類（タグ／属性／テキストに対応） |
| 親ノード／子ノード／兄弟ノード | ノードの階層関係。上＝親、下＝子、同階層＝兄弟 |

// ===== 3-1 完成コード：js/script.js =====
const text = document.querySelector('#colorText');
const color = document.querySelector('#colorPicker');

// カラーピッカーを操作したときの一連の動作
const colorBg = () => {
  // 選択した色を背景色に設定
  document.body.style.backgroundColor = color.value;

  // カラーコードを表示
  if (color.value === '#ffffff') {

  } else if (color.value === '#000000') {
    text.textContent = `カラーコード：${color.value} (black)`;
  } else {
    text.textContent = `カラーコード：${color.value}`;
  }
};

// カラーピッカーが変更されたら colorBg を発動させる
color.addEventListener('input', colorBg);

**できるようになったこと**：カラーピッカー制作を題材に、JavaScriptで **HTML要素を操作する** 一連の基礎を通した。`<input type="color">` でカラーピッカーを表示し、`<head>` に `defer` 付きで `script.js` を読み込む理由（非同期処理でページ読み込みを速くする）を理解。`document.querySelector('#ID')` で要素を取得し、`.value` でカラーコード（値）を取り出し、`.textContent`／`=`（代入）で `<p>` のテキストを書き換えるところまで。さらに、それらの操作の実体が **DOM（HTMLから作られるツリー状の内部データ構造）の操作** であること、DOMツリー・ノード・親子/兄弟関係という語彙を整理。章末では「取得 → 値の取り出し → 表示の書き換え」という、以降ずっと使う基本パターンが手に馴染んだ。

**つまずき・気づき**
- **`querySelector` の「S」は大文字**。ここは1文字でも間違えると `null` になり、しかもエラー文が出ず「静かに」失敗するので気づきにくい。`null`＝「そんなIDないよ」と覚え、`null` が出たら真っ先にスペルと大文字小文字を疑う、という手順が身についた。
- **`.value` を付け忘れると「タグそのもの」が取れてしまう**。取りたいのは「値（カラーコード）」なので、`要素.value` まで書いて初めて欲しいデータになる。「要素を取る」と「値を取る」は別ステップだと意識する。
- **`=` は「等しい」ではなく「代入」**。数学の癖で読むと `textContent = 'カラーコード：'` が「等しいかどうかの判定」に見えてしまうが、実際は「右を左に入れる（置き換える）」。この読み替えは3-1完成コードの `if (color.value === '#ffffff')` の `===`（比較）との違いにも直結する重要ポイント。※本節（3-4）では代入の `=` のみ登場。比較の `===` は3-1の完成コードで先出しされているが、詳しい解説は本まとめの範囲（3-5まで）では未登場。**※未確認**：`===` の正式な解説がどの節かは本文からは特定不可（後続の節で扱われると推測）。
- **`textContent` と `innerHTML` の違い** が明確になった。タグを「ただの文字」として出すか「有効なHTML」として出すかの違い。今は文字だけ変えたいので `textContent`、見出しにしたいなら `innerHTML`。
- **DOMという概念で腑に落ちた**：3-4で「HTMLファイルを書き換えている」のではなく「DOMを操作している」という説明で、これまでの `querySelector` 操作の“正体”が繋がった。HTML（設計図）→ DOM（内部の構造体）→ Webページ（表示）という3段階を意識すると、「なぜJavaScriptでページを後から変えられるのか」が説明できる。
- **`width` の数値ゆれ**：3-1完成コードの `style.css` は `width: 12.5rem;`、3-2本文の `style.css` は `width: 14rem;` と **数値が異なる**。制作の途中段階（3-2）と最終形（3-1掲載の完成版）で値を調整したためと思われる。手を動かす際はどちらでも表示は成立するが、完成形に合わせるなら `12.5rem`。**※要確認（教材内の表記差）**。
- **`defer` の3パターン比較**は図で見ると一気に理解できた。「head で defer なし＝解析が止まる／body 直前＝止まらないが速くはならない／head で defer あり＝止まらず同時読み込み＆解析後に実行で速い」。丸暗記でなく「なぜ head + defer が推奨か」を説明できるようにしておく。

**何をしたか（3-6 テンプレート文字列で表示させよう）**
- **カラーコードをページに表示させる**：これまで `console.log()` でコンソールに出していたカラーピッカーの値を、ID `colorText` のテキスト部分に表示させる。`textContent` の代入先を、文字列 `'カラーコード：'` から **`document.querySelector('#colorPicker').value`**（クォーテーションを外す）に変更。保存すると、ブラウザーのカード内に **`#000000`** とカラーコードが表示された。→ 表示できたので、コンソール用の `console.log(document.querySelector('#colorPicker').value);` の行は削除してよい。
- **通常のテキストと取得した値を組み合わせる**：本来は **「カラーコード：#000000」** のように、**文字列＋取得した値** を組み合わせて表示したい。まず「ひとまずそのままくっつけて」書いてみると——
  - `... .textContent = 'カラーコード：' document.querySelector('#colorPicker').value;`
  - → カラーコードもテキストも表示されず、コンソールに **`Uncaught SyntaxError: Unexpected identifier 'document'`**（`script.js:1:63`）というエラー。文字列と値を「ただ並べる」だけでは繋がらない。
- **① 「+」を使う書き方（連結の1つめ）**：通常のテキストと、取得した値や式などを組み合わせる書き方は2種類ある。1つめは **`+` 記号で繋ぐ**方法。`'カラーコード：'` と `document.querySelector('#colorPicker').value` の間に `+` を入れる。
  - `... .textContent = 'カラーコード：' + document.querySelector('#colorPicker').value;`
  - → 想定通り **「カラーコード：#000000」** と表示された。ただし、連結したい文字列や値が増えると **可読性が下がる**。さらに、本当に足し算がしたくて `+` を使ったときに混乱しやすいデメリットもある。
- **② テンプレート文字列を使う書き方（連結の2つめ・本書採用）**：そこで採用されたのが **テンプレート文字列**（**テンプレートリテラル** とも呼ぶ）。書き方は——
  - まず最終的に表示したい内容 **全体を `` ` ``（バックティック／バッククォート）で囲む**。
    - （この段階：`` `カラーコード：document.querySelector('#colorPicker').value` `` ）→ すべてが文字列扱いになり、**JavaScriptのコードがそのまま文字として表示** されてしまう。
  - 次に、**式や値・変数・定数など文字列以外のコードを `${` と `}` で囲む**。
    - `... .textContent = `カラーコード：${document.querySelector('#colorPicker').value}`;`
  - → 想定通り **「カラーコード：#000000」** と表示。`+` より少し短く書け、**文字列の中にコードを挿入していく** イメージなので見通しがよい。`+` だとクォーテーションや `+` が何度も出て入力しづらく可読性も落ちるため、**本書はテンプレート文字列を採用**。
- **3-6 COLUMN：気軽にJavaScriptを試せるオンラインツール② JSFiddle**：P.030 で紹介した CodePen 同様、HTMLの欄には基本的に `<body>` 内の部分のみ記述する。コードの実行は画面左上の [Run] ボタン、画面右上の「Settings」で入力画面の細かい調整が可能。有料版はコードのグループ化・非公開が可能。https://jsfiddle.net/

**何をしたか（3-7 定数でコードをスッキリまとめよう）**
- **定数とは**：長い文字列・計算式・繰り返し使う値などを、何度も入力するのは面倒。そこで役立つのが **定数**。定数は **いろいろな文字列・数値・式などを入れておける「箱」** のようなもの。箱に何が入っているか分かるよう **名前のラベル（＝定数名）** を貼って管理・使い回す。定数を使うと、余計な記述ミスを防いだり、何のコードかを分かりやすく整理できる。
- **定数の基本の書き方**：まず「定数を使います」と **宣言** する。宣言は **`const`** というキーワードのあとに半角スペースを入れ、続けて **定数名** を書く。定数名の後に **`=`（イコール）** を使って、定数に入れる値を指定する。
  - 記述例：`const 定数名 = 中に入れる値;`
  - このときの `=` は「等しい」ではなく **「左側の定数に割り当てる／代入する」** 意味（3-4の代入と同じ）。
  - **宣言済みの定数を使うときは `const` は不要**。定数名だけを指定すれば、中の値を取り出して利用できる。
- **簡単な例（name に文字列を入れて出力）**：
  - `const name = 'Mana';` … 「name」という定数に「Mana」という文字列を入れている
  - `console.log(name);` … → コンソールに **`Mana`**（＝入れておいた値）が表示される
- **カラーピッカーのコードを定数でまとめる**：取得した ID `colorText` と ID `colorPicker` の2つを定数にする。短い名前の箱に入れておくと、今後コードを追加するときも見やすくミスも減る。
  - `const text = document.querySelector('#colorText');`（`text` に代入）
  - `const color = document.querySelector('#colorPicker');`（`color` に代入）
  - そして利用箇所を定数に置き換える：`text.textContent = `カラーコード：${color.value}`;`
  - → Webページ上の表示（`カラーコード：#000000`）は変化なし。しかしコードはかなりスッキリ読みやすくなった。
- **定数名を付けるときのルール**：定数名は読みやすいコードにするためのルールを守った上で、**何のデータが入っている定数なのか分かりやすい名前** にするとよい。
  - **半角英数字・`$`・`_` のみ使える**：定数名に使える文字は半角英数字と `$`（ドルマーク）・`_`（アンダースコア）。**数値で始めることはできない**。CSSでよく使う `-`（ハイフン）は **JavaScriptでは使えない**。

    | 良い例 | 悪い例 |
    |---|---|
    | myColor | my-color（ハイフン不可） |
    | color1 | 1color（数字始まり不可） |
  - **POINT**：厳密には日本語も利用できるが、一般的には使われない。
  - **POINT（キャメルケース）**：`myColor` のように、**2単語目以降の最初の文字を大文字にする書き方をキャメルケース** と呼ぶ。JavaScriptではキャメルケースで記述することが多い。
  - **スペースは使えない**：定数名にスペースは入れられない（`my color` は不可）。複数単語を繋ぎたいときは大文字にする（キャメルケース）かアンダースコアを使う。
  - **予約語は使えない**：JavaScriptの言語仕様上、特別な意味を持つキーワード（**予約語**）は定数名に使えない。一覧：
    `break / case / catch / class / const / continue / debugger / default / delete / do / else / export / extends / finally / for / function / if / import / in / instanceof / new / return / super / switch / this / throw / try / typeof / var / void / while / with / yield`
  - **POINT**：今後、予約語とされるキーワードが増える場合もある。事前に確認しておくとよい（字句文法 - JavaScript | MDN：https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Lexical_grammar#キーワード ）。

**何をしたか（3-8 カラーコードを表示する「きっかけ」を作ろう）**
- **きっかけ（イベント）とは？**：これまでのプログラムは、Webページを表示したときに **すぐ実行** されていた。しかし本章で作りたいのは **「カラーピッカーで色を選んだとき」** に動作させること。ボタンのクリック・テキスト入力・スクロールなど、ユーザーの操作に応じて動作を引き起こす **「きっかけ」を JavaScript は検知できる**。この「きっかけ」を **イベント** と言う（詳細は P.092「4-1 イベントとは？」）。ここでは「イベント＝きっかけ」とやさしく覚えておく。
- **イベントの基本の書き方**：イベントの設定には **`addEventListener()`** メソッドを使う。最初に **きっかけとなる要素** を書いて `.`（ピリオド）で繋ぎ、`addEventListener()` を書く。カッコの中には **イベント** と、**そのイベントが発生したら実行される動作内容** を **`,`（カンマ）** で区切って書く。
  - 記述例：`何が.addEventListener(どうなったら, どうなる);`
  - 今回の実装（3本立て）：**①（カラーピッカーで）色が → ②選択されたら → ③カラーコードを表示する**
  - 当てはめると：`色が.addEventListener(選択されたら, カラーコードを表示する);` を script.js の一番下に書き足していく。
- **① 「何が」を指定する**：きっかけとなる要素はカラーピッカー＝前節で `color` という定数名を付けた部分。定数名をそのまま指定 → `color.addEventListener(選択されたら, カラーコードを表示する);`
- **② 「どうなったら」を指定する**：今回のカラーピッカーは `<input>` タグを使った色の入力欄。クリックで色を選択できるが、仕様上は **入力している値** になる。そこでイベント名として **`'input'`** と記述する。**イベント名は文字列扱いなので、シングルクォーテーションで囲む** 必要がある。
  - `color.addEventListener('input', カラーコードを表示する);`
  - **POINT**：今回はたまたまタグ名の「input」とイベント名がかぶっているが、タグ名を書いているわけではないので注意。イベントの種類は P.092「4-1」で詳しく紹介。
- **③ 「どうなるか」を指定する**：イベントが起きたときの処理は、あとでまとめるとして一旦 **`colorBg`** という名前にして書いておく（「colorBg という処理を実行してね」の意味）。**これはシングルクォーテーションで囲む必要はない**（文字列ではなく処理の名前だから）。
  - `color.addEventListener('input', colorBg);`
  - この段階ではまだ動作内容を用意しておらず名前だけなので、変化はない。コンソールを見ると **`Uncaught ReferenceError: colorBg is not defined`**（`script.js:7:33`）というエラー。これは「colorBg を発動してねと言ってるけど、colorBg なんて用意されていないよ？」という意味 → 次節（3-9）で `colorBg` の中身（動作内容）を書く。

**何をしたか（3-9 関数で選んだ色を取得しよう）**
- **関数とは**：「同じような処理を好きな場所で実行したい」「何かをきっかけにして実行したい」場面で、**処理をひとまとめにしたもの** を **関数** と呼ぶ。一連の動作に名前をつけて、発動させたいときに **呼び出して利用** する。
  - **たとえ（洗濯機）**：昨今の洗濯機は「洗う → すすぐ → 脱水」が **1つの「洗濯」ボタン** で完了する。この「洗濯」ボタンが関数と言える。ひとまとめでなければ、洗う→終わったらすすぐ→終わったら脱水…と1つずつ操作が必要。処理を関数にまとめれば **呼び出すだけ** で実行できる。単一処理・繰り返さない処理でも、関数を使うとコード全体がシンプルで読みやすくなり、後から見返す・他人が読むときも理解しやすい。
- **関数の基本の書き方（アロー関数）**：最初に、ひとまとめにする動作に名前（**関数名**）をつける。3-7 の `const` を使った定数と同じく **`const` を使って指定**。関数名のあとの `=`（イコール）に続いて **`()`（丸カッコ）** を書く（この丸カッコは必ず必要）。さらにそのあとに **イコールと大なり記号を組み合わせた `=>`** を書く。この部分が矢印のように見えることから **アロー関数** と呼ばれる。そのあとに続く **`{ }`（波カッコ）** の中に、関数名が呼び出されたときに何をするかを指定する。この一連の流れを **関数を定義する** と言う。
  - 記述例：
    ```
    const 関数名 = () => {
      // ここに実行する内容を書く
    };
    ```
- **function を使った書き方（別解）**：`function` というキーワードを使う方法もあり、アロー関数と区別して **function 構文** などと呼ぶ。`function` のあとに関数名と丸カッコを書き、波カッコの中に処理内容を書く。
  - 記述例：
    ```
    function 関数名() {
      // ここに実行する内容を書く
    }
    ```
  - **歴史的には function の方が古く、アロー関数は新しい書き方**。厳密には細かい機能の違いがあるが、アロー関数は最低限の機能を持つシンプルな書き方なので、**特に理由がなければアロー関数を使う** とよい。→ **本書はアロー関数を採用**。
- **カラーピッカー用の関数を作る**：今までの作業で付けていた **`colorBg`** が関数名になる。今は関数名だけ用意した状態なので、その関数を使うと何が起こるかを指定する。発動させたい機能自体（カラーコードを表示する処理）はすでに用意済み——`text.textContent = `カラーコード：${color.value}`;` の部分。この行を **`const colorBg = () => {` と `};` で囲んで関数として定義** すれば完成。
  - **変更前**：
    ```
    const text = document.querySelector('#colorText');
    const color = document.querySelector('#colorPicker');

    text.textContent = `カラーコード：${color.value}`;

    // カラーピッカーが変更されたら colorBg を発動させる
    color.addEventListener('input', colorBg);
    ```
  - **変更後**（`text.textContent = ...` を関数として定義）：
    ```
    const text = document.querySelector('#colorText');
    const color = document.querySelector('#colorPicker');

    const colorBg = () => {
      text.textContent = `カラーコード：${color.value}`;
    };

    // カラーピッカーが変更されたら colorBg を発動させる
    color.addEventListener('input', colorBg);
    ```
  - 読み解き：`color.addEventListener('input', colorBg);` ＝「**カラーピッカーを（color）／入力したら（'input'）／colorBg を発動（colorBg）**」。→ **カラーピッカーを入力したら（＝色を選択したら）、colorBg 関数を発動させる（＝カラーコードをテキストで表示する）** 動作が実装できた！
  - 動作確認：色を選ぶと **`カラーコード：#ff7070`／`カラーコード：#00a870`** のように、選んだ色のカラーコードが **即座に表示** される。
- **関数名を指定せず、そのまま処理を書いてもOK（無名関数）**：上の例では **あらかじめ関数を定義してから** `addEventListener()` に関数名を渡したが、実は **関数の式そのものを直接指定** することも可能。この書き方の関数を **無名関数** と言う。イベント名の後にカンマで区切り、丸カッコ以降の指示を記述する。
  - 記述例：
    ```
    const text = document.querySelector('#colorText');
    const color = document.querySelector('#colorPicker');

    // カラーピッカーが変更されたら、カラーコードを表示
    color.addEventListener('input', () => {
      text.textContent = `カラーコード：${color.value}`;
    });
    ```
  - **無名関数のメリット**：関数を事前に定義する必要も、関数の名前をつける必要もないこと。今回のような短い処理なら、関数を定義する書き方も無名関数もどちらでも大差ない。ただし **関数の処理が複雑になるとコードが読みづらくなる** ので、そんなときは **あらかじめ関数を定義** しておくとよい。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| テンプレート文字列（テンプレートリテラル） | 表示内容全体を `` ` ``（バックティック）で囲み、値や式を `${ }` で挿入する書き方。可読性が高い |
| `` ` ``（バックティック／バッククォート） | テンプレート文字列の全体を囲む記号。通常の引用符（`'` `"`）とは別物 |
| `${ }` | テンプレート文字列の中に、文字列以外のコード（値・式・変数・定数）を挿入する書き方 |
| `+`（文字列連結） | 文字列と値を繋ぐもう1つの方法。増えると可読性が下がり、足し算と混同しやすい |
| `Uncaught SyntaxError: Unexpected identifier` | 文字列と値を正しく繋がずに並べたときなどに出る構文エラー |
| 定数 | 文字列・数値・式などを入れておく「箱」。名前（定数名）を付けて使い回す |
| `const` | 定数を宣言するキーワード。`const 定数名 = 値;` の形。使うときは定数名だけでOK |
| 定数名のルール | 半角英数字・`$`・`_` のみ／数字始まり不可／`-`不可／スペース不可／予約語不可 |
| キャメルケース | `myColor` のように2単語目以降の頭文字を大文字にする命名。JSで多用される |
| 予約語 | JSが特別な意味を持たせているキーワード（const, if, for など）。定数名に使えない |
| イベント（きっかけ） | クリック・入力・スクロールなど、動作を引き起こすユーザー操作の「きっかけ」 |
| `addEventListener()` | イベントを設定するメソッド。`要素.addEventListener(イベント名, 処理)` の形 |
| `'input'` イベント | 入力欄（`<input>`）の値が入力・変更されたときに発生するイベント。文字列で指定 |
| `Uncaught ReferenceError: ... is not defined` | 用意していない名前（未定義の関数・定数など）を使ったときのエラー |
| 関数 | 一連の処理をひとまとめにして名前を付けたもの。呼び出して実行する（洗濯ボタンの例え） |
| アロー関数 | `const 関数名 = () => { ... };` の形。`=>` が矢印に見える新しめの書き方（本書採用） |
| function 構文 | `function 関数名() { ... }` の形。歴史的に古い関数定義の書き方 |
| 関数を定義する | 関数名・`()`・`=>`・`{ }` を書いて、呼び出し時の処理内容を決める一連の流れ |
| 無名関数 | 名前を付けず、関数の式そのものを `addEventListener` などに直接渡す書き方 |

// 手順1：全体をバックティックで囲む（この段階ではコードが文字として出てしまう）
// document.querySelector('#colorText').textContent = `カラーコード：document.querySelector('#colorPicker').value`;
// 手順2：文字列以外のコードを ${ } で囲む
document.querySelector('#colorText').textContent = `カラーコード：${document.querySelector('#colorPicker').value}`;
// → 「カラーコード：#000000」と表示
```

```javascript
// ===== 3-9 カラーピッカー完成コード（関数を定義して発動） =====
const text = document.querySelector('#colorText');
const color = document.querySelector('#colorPicker');

const colorBg = () => {
  text.textContent = `カラーコード：${color.value}`;
};

// カラーピッカーが変更されたら colorBg を発動させる
color.addEventListener('input', colorBg);
// color=カラーピッカーを / 'input'=入力したら / colorBg=発動
// → 色を選ぶと「カラーコード：#ff7070」等が即座に表示される
```

```javascript
// ===== 3-9 無名関数で書く場合（関数名を用意しない） =====
const text = document.querySelector('#colorText');
const color = document.querySelector('#colorPicker');

// カラーピッカーが変更されたら、カラーコードを表示
color.addEventListener('input', () => {
  text.textContent = `カラーコード：${color.value}`;
});
```

**できるようになったこと**：3-1で「完成形」として先に見せられていたコードの中身を、3-6〜3-9で1つずつ理解して自力で組み上げられた。文字列と値の連結を **テンプレート文字列（`` `...${}...` ``）** で書く方法、繰り返し使う取得結果を **`const` の定数（`text`／`color`）** にまとめてコードをスッキリさせる方法、ユーザー操作を捕まえる **`addEventListener('input', ...)`** というイベントの仕組み、そして処理をまとめる **関数（アロー関数）／無名関数** の書き方。これらを組み合わせて、**「色を選ぶ → その場でカラーコードが表示される」** という、イベント駆動の動きを持つカラーピッカーが完成した。「取得 → 定数化 → 表示（テンプレート文字列）→ イベントで発動（関数）」という、今後あらゆるUI実装で使う基本の型が一通りそろった。

**つまずき・気づき**
- **文字列と値は「並べる」だけでは繋がらない**。3-6のエラー（`Unexpected identifier 'document'`）が良い教訓。繋ぐには `+` かテンプレート文字列が必要。`+` は増えると読みにくく足し算と紛らわしいので、**基本はテンプレート文字列** で書く癖をつける。`${ }` の中に「文字列以外（値・式・定数）」を入れる、という切り分けが要。
- **バックティック `` ` `` は普通の引用符とは別物**。シングル/ダブルクォートで囲むと `${ }` が展開されず、コードが文字としてそのまま出る（3-6の失敗例）。キー入力の場所も違うので最初は戸惑うポイント。
- **`const` の `=` は「代入」**（3-4・3-7で繰り返し強調）。定数は「箱にラベルを貼って値を入れる」イメージ。宣言時だけ `const` が要り、**使うときは定数名だけ** という区別も掴めた。
- **定数名のルールは “CSSの癖” に注意**。CSSでは `my-color` のようにハイフンを使うが、**JSではハイフン不可**（引き算と解釈される）。JSは **キャメルケース（`myColor`）** が定番。数字始まり・スペース・予約語も不可。予約語一覧（const, if, for, function…）は「変数・定数名に使えない特別な語」としてざっと眺めておく。
- **`addEventListener` の3要素**が明確になった：**何が（要素）.addEventListener(どうなったら（イベント名・文字列）, どうなる（処理・関数名））**。イベント名 `'input'` は**文字列なのでクォート必須**、処理名 `colorBg` は**関数の名前なのでクォート不要** ——この“クォートを付ける/付けない”の線引きが最初の関門。
- **`ReferenceError: colorBg is not defined` は「名前だけ先に使った」サイン**（3-8）。`addEventListener('input', colorBg)` を先に書き、`colorBg` の中身（関数定義）は3-9で用意する、という「先に呼び出し・後で定義」でも、定義さえあれば動く（アロー関数は巻き上げの挙動が var 関数と違う点は本書範囲外だが、完成コードは定義が呼び出しより前にあるので問題なし）。※このあたりの厳密な挙動は本まとめの範囲では未解説。**※未確認**。
- **「なぜ即座に表示されるようになったか」**が腑に落ちた。3-5までは「ページ読み込み時に1回だけ実行」だったが、3-8〜3-9で **イベント（input）にひも付けて関数を発動** させたことで、「操作するたびに処理が走る」動的な挙動になった。これがJavaScriptらしさ（1-1で学んだ「読み込み後もリアルタイムに書き換えられる」）の実体だと繋がった。
- **アロー関数 vs function vs 無名関数** の使い分け：本書は **アロー関数** を基本採用。短い処理なら **無名関数**（その場に直接書く）でも良いが、**処理が複雑なら事前に関数定義** した方が読みやすい、という判断基準を得た。まずはアロー関数の形 `const 名前 = () => { 処理 };` を手に馴染ませる。

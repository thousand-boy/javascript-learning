### 5-2｜insertAdjacentHTML でHTMLタグを挿入しよう（textContent との違い）

**何をしたか**
- **5-2（p.149〜151／サンプル `chapter5/02-demo`）**：**画像やテキストなど、HTMLタグを含めたコンテンツをJavaScriptによって挿入** する節。HTMLには **「menu」というIDがついた空の `<div>`** を用意し、**ここに画像やテキストを入れるようJavaScriptで指示** します。CSSは **レイアウトを整える以外特別な指定はありません**。
- **定数の用意（p.150）**：**ID「menu」のdivを定数 `menu` に入れ**、**挿入したいコンテンツをテンプレート文字列で定数 `content` にまとめます**。**この時点では定数に入れただけなので、ブラウザーには何も表示されません**。
- **まず `textContent` で試す → 失敗（p.150）**：**すべての内容がそのまま文字列として表示されていてHTMLタグとして認識されていません**。
- **`insertAdjacentHTML()` を使う（p.151）**：**HTMLを挿入したい要素を指定し、カッコの中には第一引数にHTMLの挿入位置、第二引数に挿入したい内容を指定**。挿入位置は4種類（下表）。今回は **`beforeend` にして、divの閉じタグの直前に要素を追加**。**挿入位置は文字列としての扱いになるのでシングルクォーテーションで囲む必要があり**、**挿入内容は定数名を呼び出すのでクォートは不要**。→ **イチゴジュースの画像が、文字列としてではなくHTMLのタグとして認識されて表示**されました。
- **※脚注（p.151）**：**`innerHTML` はHTMLタグを追加するのではなく置換するため、元々あったHTML要素がなくなります。イベントを設定した際に意図しない動作を招く恐れもあるので本書では使用しません**。

**挿入位置の4種類（p.151）**

| 挿入位置 | 意味 | 位置のイメージ |
|---|---|---|
| `beforebegin` | 要素の直前に挿入 | `<div>` の **前** |
| `afterbegin` | 要素内部の、最初の子要素の前に挿入 | `<div>` の **直後（内側の先頭）** |
| `beforeend` | 要素内部の、最後の子要素の後に挿入 | `</div>` の **直前（内側の末尾）** |
| `afterend` | 要素の直後に挿入 | `</div>` の **後** |

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `insertAdjacentHTML()` | 指定した位置にHTMLタグごとコンテンツを挿入するメソッド |
| 第一引数／第二引数 | 「挿入位置」（クォートあり）／「挿入内容」（定数名なのでクォートなし） |
| `textContent` の限界 | タグも「ただの文字」として表示され、HTMLとして解釈されない |
| `innerHTML` | HTMLタグを扱えるが **追加ではなく置換**。既存要素が消えるため本書では不使用 |
| テンプレート文字列（`` ` ` ``） | バックティックで囲む文字列。`${}` で値を埋め込める |

**学んだ主な構文**

```js
// ===== 5-2 記述例と完成形（p.151／js/script.js） =====
要素.insertAdjacentHTML('挿入位置', 挿入内容);

const menu = document.querySelector('#menu');
const content = `<div><img src="images/strawberry.jpg" alt=""></div>`;
//menu.textContent = content;                    // ← タグが文字列として出てしまうのでコメントアウト
menu.insertAdjacentHTML('beforeend', content);   // ← beforeend＝divの閉じタグの直前に追加
```

**できるようになったこと**：`textContent` では **タグが文字列として出てしまう** ことを実際に確認したうえで、`insertAdjacentHTML()` に **第一引数＝挿入位置（クォートあり）／第二引数＝挿入内容（クォートなし）** を渡す書き方を習得。4つの挿入位置の違いも説明できます。

**つまずき・気づき**
- **`textContent` がタグを文字列として出すのは仕様であり、安全側の挙動**。ユーザー入力を出す場面ではむしろ正解で、MDNも <cite index="6-1">ユーザー提供のコンテンツがプレーンテキストだとわかっている場合は `insertAdjacentText()` や `textContent` を使うべき</cite>としている。
- **`insertAdjacentHTML()` は無条件に安全ではない**。MDNによれば <cite index="2-1">このメソッドは `<script>` やイベントハンドラー属性などXSSに危険な要素を取り除くサニタイズを一切行わない</cite>。今回は固定文字列なので問題ないが、**外部から来た文字列をそのまま渡すのは危険**。※教材の範囲外の補足。
- **`innerHTML` を避ける理由が「置換だから」と明示されているのが良い**。子要素が作り直されるため、**`addEventListener` を設定していた要素はイベントが外れて動かなくなる**。
- **`'beforeend'` はクォート必要／`content` は不要** の対比は、4章の `classList.add('クラス名')` と `btn.disabled = isAgreed.checked` の関係と同じ。**「文字列そのもの」か「箱の呼び出し」か**を毎回意識する。

### 5-3｜配列で複数の画像のファイル名をまとめよう（配列・要素・インデックス）

**何をしたか**
- **5-3（p.154〜157／サンプル `chapter5/03-demo`）**：表示したい画像は6つ。**1つひとつを定数にすると定数の数が膨大になり、コピー＆ペーストではミスも増え、管理も大変**。
- **配列とは（p.154）**：教材ハイライト → **配列を使うと、1つの定数で複数のデータをまとめてグループ化できるので、値が増えても定数を増やす必要はありません**。**定数は1つの箱、配列は複数のものを入れておける仕切りのついた箱**という比喩。
- **要素とインデックス（p.155）**：**配列に入れられる値を「要素」**、**各要素のスペースに割り振られる0から始まる番号を「インデックス」** と呼びます。組み合わせることで **「〇〇の箱の中にある△番目のデータ」** と指し示せ、**中身が100個や1000個に増えても定数名は同じものが使える**。
- **POINT（p.155）**：**配列の「要素」はHTMLの「要素」と同じ呼び方だが別物なので混同しないように**。
- **書き方（p.155）**：**`[ ]`（角カッコ）で囲み、要素を `,`（カンマ）で区切る**。**登録できる要素の数に制限はなく**、**データ型はなんでもOK（混在も可だが扱いが複雑になるので注意）**。
- **メニューリストに適用＋確認（p.156〜157）**：定数 `lists` を作成（**要素を一覧で見やすくするため改行**）。`console.log(lists);` で出力すると **`(6)` は要素の数**を示し、**三角形をクリックすると詳細（`0:` 〜 `5:`、`length: 6`）を閲覧できます**。**この時点では表示に使っていないので見た目は変わりません**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| 配列 | 1つの定数に複数のデータをまとめられるデータ型。「仕切りのついた箱」 |
| 要素（配列の） | 配列に入れられる値。**HTMLの「要素」とは別物** |
| インデックス | 各要素に割り振られた **0から始まる** 番号 |
| `[ ]` / `,` | 配列を作る記号／要素同士の区切り |
| `console.log(配列名)` | 配列の中身をまとめて出力できる。先頭の `(6)` は要素数 |

**学んだ主な構文**

```js
// ===== 5-3 記述例とデータ型（p.155） =====
const 定数名 = [要素1, 要素2, 要素3];

const numbers = [1, 20, 45, 31];                 // 数値
const name = ['Mana', '達也', '勇太', 'みずほ'];   // 文字列
const mix = ['Mana', 20, true];                  // データ型が混ざっている
```

```js
// ===== 5-3 メニューリストに配列を導入（p.156／js/script.js） =====
const lists = [
    'strawberry.jpg',
    'lime.jpg',
    'mango.jpg',
    'lemon.jpg',
    'fig.jpg',
    'apple.jpg',        // ← 「,」を忘れずに（見やすさのため改行している）
];
console.log(lists);     // → (6) ['strawberry.jpg', … ]。展開すると 0:〜5:, length: 6
```

**できるようになったこと**：`[ ]` とカンマで配列を作り、1つの定数名で複数データを管理する書き方を習得。要素とインデックス（0始まり）の関係を説明でき、コンソール出力の `(6)` や展開表示も読めるようになりました。

**つまずき・気づき**
- **末尾カンマ（trailing comma）は誤りではない**。MDNによれば <cite index="9-1">JavaScriptは配列リテラルで当初から末尾カンマを許容しており、複数行のリストで項目を追加・削除・並べ替えするときに変更行数が減るので編集にも差分レビューにも役立つ</cite>。ただし <cite index="9-1">2つ以上続けると「穴」ができて疎な配列になり、`[1, 2, 3, , ,]` の length は5になる</cite>ので打ちすぎに注意。**JSONでは末尾カンマは書けない**点も別物として押さえたい。
- **「配列の要素」と「HTMLの要素」の名前衝突** をPOINTで注意しているのが親切。今後 `lists[0]` と `querySelector()` が同居するので混同しない。
- **`const` で宣言した配列でも中身は扱える**。`const` は **再代入を禁じるだけ**で、中身の変更は禁じない。※教材にはない自分の補足。

### 5-4｜配列の中にある画像を表示しよう（インデックス指定・undefined）

**何をしたか**
- **5-4（p.158〜162／サンプル `chapter5/04-demo`）**：前節は **配列という箱がそのまま表示されただけ**なので、**箱の中身を1つずつ取り出す** 方法を学びます。
- **取り出し方（p.158）**：**配列の定数名に続けて `[ ]` を書き、その中に取り出したい要素のインデックスを指定**（`lists[0]`）。教材ハイライト → **インデックスは「0」からはじまるので、通常数えるところの1番目は配列では0番目**。**要素が存在しないインデックスを指定した場合は `undefined`**（＝「その箱の指定された番号のスペースには何も入ってないよ」）。
- **コンソールで検証（p.159）**：`console.log(lists[0]);` → `strawberry.jpg`、`[1]` → `lime.jpg`、`[2]` → `mango.jpg`。**確認できたらコメントアウト**。
- **画像表示に反映（p.159〜161）**：定数 `content` の **`strawberry.jpg` をテンプレート文字列で `${lists[0]}` に書き換え**。**変化がなくて確認しづらいので `${lists[1]}` でも試し**、ライムジュースの画像に変わることを確認。**6個表示したいので、`<div><img …></div>` の部分をコピー＆ペーストしてインデックスの数字を変更**。
- **次節への引き（p.162）**：**せっかく1つの配列にまとめたのに、表示したいときに何度も同じようなコードを書くのは手間がかかり管理しづらい。でも大丈夫、よりよいコードの書き方があります**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `配列[インデックス]` | 配列から要素を1つ取り出す書き方（例：`lists[0]`） |
| 0始まりのズレ | 通常数えるところの「1番目」は配列では「0番目」 |
| `undefined` | 「定義されていない」。指定した番号に何も入っていない状態 |
| `${lists[0]}` | テンプレート文字列の中に配列の要素を埋め込む書き方 |

**学んだ主な構文**

```js
// ===== 5-4 取り出しと確認（p.158〜159） =====
配列[インデックス]
console.log(lists[0]);   // → strawberry.jpg（1〜5に変えると他のファイル名）
```

```js
// ===== 5-4 画像ファイル名を配列から呼び出す（p.160） =====
//console.log(lists[0]);      // 確認できたのでコメントアウト
const content = `<div><img src="images/${lists[0]}" alt=""></div>`;
```

```js
// ===== 5-4 6個ぶんコピー＆ペーストして数字を変更（p.161） =====
const content = `<div><img src="images/${lists[0]}" alt=""></div>
    <div><img src="images/${lists[1]}" alt=""></div>
    （・・・${lists[2]}〜${lists[5]} 省略・・・）
`;
// → 6個表示できたが、同じコードの繰り返しで管理しづらい（次節へ）
```

**できるようになったこと**：`配列[インデックス]` で中身を取り出し、`${}` の中に埋め込んで **画像のファイル名を配列から動的に呼び出す** 書き方を習得。同時に **「同じコードの繰り返しは管理しづらい」という問題意識** を持てました。

**つまずき・気づき**
- **`${}` の中には式（配列アクセス）を書ける**。4章の `` `${percentage}%` `` は定数1つだったが、埋め込めるのは「値」ではなく「値になるもの」。
- **`lists[0]` では見た目が変わらず成功が確認しづらい**ので、教材自身が `lists[1]` で再検証している。**変化しない検証は検証になっていない**という考え方は自分のデバッグにも取り入れたい。
- **存在しないインデックスはエラーにならず `undefined`**。画像が出ないのに原因がわからない事故になりやすい。※エラーにならない点は自分の補足。
- **6回のコピペは、5-3で否定した「定数を6個作る」と同じ構図**。データはまとまったのに **出力側がまとまっていない**。この違和感を体験させてから繰り返し処理を教える構成。

### 5-5｜for文の繰り返し処理を理解しよう（let・ループカウンター・i++）

**何をしたか**
- **5-5（p.164〜167／サンプル `05-demo1`・`05-demo2`）**：**何度も同じコードをコピー＆ペーストするのは大変でメンテナンスもしづらい。プログラムは繰り返し処理が大の得意**という導入。**繰り返し行われる処理を「ループ処理」、繰り返し1回分を「ループ」** と呼びます。
- **変数letとは（p.165）**：**`let` は変数で、`const` によく似た値を入れておける箱**。**宣言は `let` ＋半角スペース＋変数名**で、**変数名のルールは定数名と一緒**。教材ハイライト → **大きな違いとして「const」では値の再代入ができません**。**for文では繰り返すたびに回数部分が更新される＝再代入されるので `let` を使います**。
- **3つのパート（p.165〜166）**：**`let i = 1;` は初回に実行する処理**で、この変数は **ループカウンター**（何回目かを記憶する）。**`i <= 10;` は繰り返し条件**で、比較演算子（4-9）を使い **`i` が11になると条件に当てはまらなくなり停止**。**`i++` は各繰り返し後の処理**で **`i = i + 1` と同じ意味**。`i = i + 1` / `i += 1` / `i++` は **どれでも同じように動作**し、**for文では一番短い `i++` が最もよく使われます**。
- **POINT2つ**：**`i` はプログラミングの慣習**として広く使われているので**慣習にならって `i` にしておくといい**（p.165）。**`i++` の後には `;` を書いてはいけません。書くとエラーになってプログラムが停止します**（p.166）。
- **変数 i の値を表示する（p.167）**：**`console.log()` のパラメーターをバックティックで囲みテンプレート文字列にして `${i}` を埋め込む** と「1回目のこんにちは！」〜「10回目のこんにちは！」。**出力されるたびに1が足され、回数が増えていくのがわかります**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `for` 文／ループ処理・ループ | 同じ処理を繰り返す構文／繰り返し処理と、その1回分 |
| 変数 `let` | 値を入れておける箱。`const` と違い **再代入できる** |
| 初回に実行する処理 | `let i = 1;` の部分。**初回のみ**実行 |
| ループカウンター | 何回目の繰り返しかを記憶する変数。慣習で `i` |
| 繰り返し条件 | `i <= 10;` の部分。`false` になると停止 |
| `i++` / `i += 1` / `i = i + 1` | すべて「`i` を1増やす」。for文では `i++` が定番 |

**学んだ主な構文**

```js
// ===== 5-5 記述例と例（p.164） =====
for(初回に実行する処理; 繰り返し条件; 各繰り返し後の処理){
    繰り返し実行する処理
}

for(let i = 1; i <= 10; i++){
  console.log('こんにちは！');       // → コンソール左側に「10」＝10回表示された
}
```

```js
// ===== 5-5 変数 i の値を表示する（p.167／05-demo2） =====
for(let i = 1; i <=10; i++){
    console.log(`${i}回目のこんにちは！`);   // → 1回目〜10回目
}
```

**できるようになったこと**：`for(初回処理; 条件; 各回後の処理){ }` の3パートをそれぞれ説明できるように。`let` でループカウンターを作り、比較演算子で終了条件を書き、`i++` で加算する流れを、**判定→実行→加算→判定**の1周として追えるようになりました。

**つまずき・気づき**
- **`i++` の後のセミコロン禁止を実機で検証した**。Node.js（v22）で `for(let i=1;i<=3;i++;){…}` は `Expected ')', got ';'` の **構文エラー**になり教材どおり。構文エラーなので **ファイル全体が1行も実行されない**のが厄介。※検証は自分で実施。
- **`for` の丸カッコのセミコロンは「区切り」として2つだけ**。文末のセミコロンとは役割が違う。
- **教材 p.166 の「『繰り返し条件』の部分は…」は「各繰り返し後の処理」の誤りと思われる**（直前の見出しと例示が `i++` 系）。**※教材の誤植か写真の判読ミスかは断定できず要確認**。
- **`let` の導入が「for文のため」という必要に迫られた形**なのが良い。3-7で `const` を先に教え、再代入が必要な場面で初めて `let` を出す順序。
- **無限ループの危険には触れられていない**。`i++` を書き忘れると条件が永久に `true` でブラウザーが固まる。※自分の補足。

### 5-6｜for文で画像を一覧表示しよう（lists[i]・lists.length）

**何をしたか**
- **5-6（p.168〜170／サンプル `chapter5/06-demo`）**：**同じコードを繰り返し記述していたところを、for文でまとめていきます**。**配列は繰り返し処理するfor文と相性がよく、配列をfor文で扱うことで簡単にすべての内容を表示できる**ようになります。
- **着眼点と条件（p.168）**：5-4では **`lists[0]` 〜 `lists[5]` と角カッコの数字が0から5まで1ずつ増えていた**ので、**角カッコの中にループカウンターを設定**。**開始の数字を0としたいので `let i = 0;`**、**繰り返し条件は `i < 6;` にして、6未満、つまり5までのインデックスを取得できるように**します。**`{}` ブロック内に定数 `content` と挿入コードを入れ、`lists[0]` の数字を `i` に変更して `lists[i]`** に。→ **Webページの見た目は変わりませんが、コードはすっきりとまとめられました**。
- **lengthで要素の数を取得する（p.169〜170）**：**画像を増やして要素数が変わるとfor文の条件も書き換えが必要で面倒**なので、**配列の要素数を取得できる `length` を使う**。**`length` は4-8で文字数の取得に使ったが、配列の要素の数も数えられる**（`lists.length` とピリオドでつなぐだけ）。試しに出力すると **`6`**。**この `lists.length` をfor文の繰り返し条件に書き換えれば完成** で、**要素の数が変更されたとき `length` で取得できる数字は自動的に更新されます**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `lists[i]` | 角カッコにループカウンターを入れて、要素を順番に取り出す |
| `let i = 0;` | 配列はインデックスが0始まりなので開始値も0 |
| `i < 6;` | 「6未満」＝5まで。`<=` ではなく `<` |
| `配列名.length` | 配列の要素数を返す |
| `i < lists.length` | 要素数が変わっても書き換え不要になる定番の条件 |

**学んだ主な構文**

```js
// ===== 5-6 完成形（p.170／js/script.js） =====
//console.log(lists.length);      // → 6（確認できたのでコメントアウト）

for(let i = 0; i < lists.length; i++){       // ← lists.length を使って書き換えた
    const content = `<div><img src="images/${lists[i]}" alt=""></div>`;
    menu.insertAdjacentHTML('beforeend', content);
}
```

**できるようになったこと**：6行のコピペを **3行のfor文にたたむ** リファクタリング。「インデックスが1ずつ増える」パターンにループカウンターを差し込み、さらに固定値 `6` を `lists.length` に置き換えて、**配列を増減してもコードを触らなくてよい状態** にできました。

**つまずき・気づき**
- **`i < 6` → `i < lists.length` への置き換えがこの節の本質**。前者はデータとコードの二重管理で、後者にすると **「配列が唯一の情報源」** になる。
- **`length` は「個数」であって「最後のインデックス」ではない**ので `<` と組み合わせるのが自然。`<=` にすると1回多く回って `undefined` を掴む（エラーにならず画像だけ出ない）。※補足は自分の理解。
- **`const content` がループの中にあってよい**のは、`{}` ブロックの中で毎回作り直されるから。※スコープの話は教材では未説明。
- **見た目が変わらないリファクタリングを「成功」と呼べるようになった**。教材も「見た目は変わりませんが、コードはすっきりとまとめられました」と明言している。

### 5-7｜変数letと定数constの違いとは？（再代入とエラー）

**何をしたか**
- **5-7（p.172〜174／サンプル `chapter5/07-demo`）**：**箱には中身を変更できる変数 `let` と、最初から最後まで中身が変わることのない定数 `const` があり、箱の中身を変更することを「再代入」といいます**。
- **letで再代入（p.172）**：`let letName = 'マナ';` → 「マナ」。**別の値を代入すると「メアリー」に変わり、これが「再代入された」ということ**。**再代入するとき、変数名の前に `let` は書きません**。**元々あった値は削除されます**（p.173の図＝古い値がゴミ箱へ）。
- **constで再代入（p.173）**：`const constName = '大本';` に別の値を再代入すると **`Uncaught TypeError: Assignment to constant variable.`**。**これは「定数を書き換えようとしているよ！ だめだよ！」という意味**で、**エラーが起きるとそれ以降のコードは無視されるため、その後の `console.log()` は実行されません**。
- **どう使い分けるのか（p.174）**：**できることが多い `let` の方が使い勝手がよさそうに見えるかもしれませんが、近年のJavaScriptの書き方としては定数の `const` を積極的に使います**。メリットは **①意図せず別の値を再代入してしまうミスを防げる ②コードを読むときに、値が再代入されている可能性を考える必要がない**。**基本的には `const` を使い、再代入が必要な場合のみ `let` を使う**。図では `let age = 26;` を読む人が「途中で変わったかな…?」と悩み、`const age = 26;` なら「これは26だね！」と即断できる対比が描かれています。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| 再代入 | 箱の中身（値）を別の値に変更すること |
| `let` / `const` | 中身を変更できる箱／再代入すると即エラーになる箱 |
| 再代入時の書き方 | 2回目以降は `let` を付けず `変数名 = 値;` |
| `Uncaught TypeError: Assignment to constant variable.` | 定数を書き換えようとしたときのエラー |
| 使い分けの原則 | **基本は `const`、再代入が必要な場合のみ `let`** |

**学んだ主な構文**

```js
// ===== 5-7 let と const の対比（p.172〜173） =====
let letName = 'マナ';
letName = 'メアリー';        // ← 2回目は let を書かない。元の 'マナ' は削除される
console.log(letName);       // → メアリー

const constName = '大本';
constName = '高橋';          // → Uncaught TypeError: Assignment to constant variable.
console.log(constName);     // ← エラー以降なので実行されない
```

**できるようになったこと**：`let` と `const` の違いを「再代入できるか」の一点で説明できるように。`const` への再代入が `TypeError` になり **エラー以降の行が実行されない** ことを理解し、**制約がある方が読み手にとって親切** という価値観を持てました。

**つまずき・気づき**
- **エラーメッセージを実機で再現した**。Node.js（v22）でも `TypeError: Assignment to constant variable.` と教材どおり。ブラウザーでは先頭に `Uncaught` が付く（どこにも捕捉されなかった例外という意味）。※検証は自分で実施。
- **「それ以降のコードは無視される」の粒度に注意**。5-7は **実行時エラー**なのでエラー行より前は実行済み。5-5の `i++;` のような **構文エラー**はファイルが1行も実行されない。※区別は自分の補足。
- **「エラーも出にくい `let` の方が便利そう」→「でも `const` を積極的に使う」** の流れが一番の学び。**エラーをコストではなく安全装置とみなす**発想の転換。
- **`const` は「値が変わらない」ではなく「再代入できない」**。配列やオブジェクトを入れた場合は中身の変更ができる。5-8以降で混乱しないよう区別しておく。※補足は自分の理解。

### 5-8｜オブジェクトで画像、メニュー名、値段をまとめよう（プロパティ・キー・値）

**何をしたか**
- **5-8（p.175〜179／サンプル `chapter5/08-demo`）**：**「450円です。」と突然言われても意味がわからない**が、**「メニュー名はイチゴジュースです。画像ファイルはstrawberry.jpgです。値段は450円です。」なら意味がわかる**。**情報はバラバラだとうまく伝わらず、正しく伝えるにはひとまとめにして管理する必要があります**。
- **オブジェクトとは（p.175）**：**複数のデータをひとまとまりにしたもの**。**配列は番号でデータにアクセスしましたが、オブジェクトはさらに任意の名前が使えます**。**配列が「仕切り付きの箱」なら、オブジェクトはその仕切りにわかりやすいラベルが貼ってあるイメージ**。身近な「ノート」「犬」「紅茶」を例に図解。
- **プロパティ、キー、値（p.176）**：**項目ごとに分かれているデータを「プロパティ」、項目名を「キー」（プロパティ名）、キーに対する内容を「値」** と言います。
- **書き方（p.176〜178）**：**`{}`（波カッコ）を使い、配列と同じように一般的には定数に保存**。**プロパティが複数ある場合は `,` で区切り、最後のプロパティのカンマは省略可能**（ただし **今後追加や削除する場合に管理しやすくなるのでつけておくといい**）。**キーは好きな名前を付けられ、値との間を `:`（コロン）で区切ります**。**値のデータ型に制限はなく、文字列や数値はもちろん、配列、オブジェクト、関数なども格納できます**。
- **実装とPOINT（p.178）**：`strawberry` オブジェクト（`name` / `img` / `price`）を追加。**メニュー名と画像ファイルは文字列、値段は数値**。**数値にしておけば、あとから計算したり、値段順に並べ替えるなどの機能をつけられます**。
- **コンソールで確認（p.179）**：`console.log(strawberry);` → **`{name: 'イチゴ', img: 'strawberry.jpg', price: 450}`** と **値がキーとセットで管理されているのがわかります**。**「Object」とだけ表示された場合はページを更新して再度確認**。**この段階ではまだ情報をまとめただけ**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| オブジェクト | 複数のデータをひとまとまりにしたもの。**仕切りにラベルが貼ってある箱** |
| 配列との違い | 配列は**番号（インデックス）**、オブジェクトは**任意の名前（キー）** |
| プロパティ／キー／値 | 項目ごとのデータ／その項目名／キーに対する内容 |
| `{}` / `:` / `,` | オブジェクトを作る記号／キーと値の区切り／プロパティ同士の区切り（末尾は省略可） |
| 値のデータ型 | 制限なし。配列・オブジェクト・関数も値にできる |

**学んだ主な構文**

```js
// ===== 5-8 オブジェクトの書き方（p.176〜177） =====
const 定数名 = {
    キー1: 値1,       // ← 必須のカンマ
    キー2: 値2,
    キー3: 値3,       // ← 最後のカンマは省略可能（付けておくと管理しやすい）
};
```

```js
// ===== 5-8 メニューリストに追加（p.178〜179／js/script.js） =====
const strawberry = {
    name: 'イチゴ',              // メニュー名（文字列）
    img: 'strawberry.jpg',      // 画像ファイル（文字列）
    price: 450,                 // 値段（数値 ← 計算や並べ替えのため）
};
console.log(strawberry);        // → {name: 'イチゴ', img: 'strawberry.jpg', price: 450}
```

**できるようになったこと**：`450` と `price: 450` の違いを説明できるように。`{}` の中にキーと値をコロンで結んだプロパティを並べる書き方を習得し、**データ型の選択が将来の機能を左右する**（値段を数値にしておく）視点も得ました。

**つまずき・気づき**
- **箱の比喩が3段階で拡張されている**。定数＝1つの箱（3-7）→ 配列＝仕切り付きの箱（5-3）→ オブジェクト＝仕切りにラベルが貼ってある箱（5-8）。
- **コンソールの展開表示が `img` → `name` → `price` とアルファベット順**になっている点に気づいた。ソースの記述順は `name` → `img` → `price` で、Node.js の `Object.keys()` でも記述順が保たれる。並べ替えているのはDevTools側で、Chromeの更新情報でも <cite index="19-1">プロパティを「アルファベット順に並べ替える」トグルが既定で有効</cite>と説明されている。**コンソールの見た目とデータの実態を混同しない**教訓。※検証と指摘は自分で実施。
- **`{}` が「オブジェクト」と「ブロック」で同じ記号**なのは紛らわしい。**`=` の右側ならオブジェクト、文の後ならブロック**と位置で見分ける。※自分の整理。
- **「Objectとだけ表示されたらページを更新」という但し書き**は実践的。表示が期待と違うときはまずリロード。

### 5-9｜オブジェクトの情報を取得しよう（ドット記法・ブラケット記法）

**何をしたか**
- **5-9（p.180〜182／サンプル `chapter5/09-demo`）**：**配列はインデックスで値を取得していましたが、オブジェクトにはインデックスがありません。かわりにあるのがキーです**。書き方は2通り。
- **ドット記法（p.180）**：**オブジェクトに `.`（ドット）とキーをつなげて書く方法**（`strawberry.name`）。
- **ブラケット記法（p.180）**：**オブジェクト名のあとに `[ ]` を書き、その中にキーを文字列として書く方法**。**キーは文字列として扱うので、シングルクォーテーション（またはダブルクォーテーション）で囲む必要があります**（`strawberry['name']`）。
- **実践（p.181）**：ドット記法で `name`、ブラケット記法で `img` を出力 → **どちらも取得できています**。
- **どちらを使えばいいか（p.182）**：**基本的には書きやすくて見た目もシンプルなドット記法で問題ありません**。**ただし、キーを指定する際に定数や変数を利用したい場合は、ブラケット記法にする必要があります**。**定数名 `key` を使って値を取得できるのはブラケット記法のみで、ドット記法を使うと `undefined` となってしまいます**。**2つの書き方を混在すると読みにくくなるので、基本的にはドット記法で統一し、キーを定数で指定する必要がある場合に限りブラケット記法を使う**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| ドット記法 | `オブジェクト名.キー`。**基本はこちら** |
| ブラケット記法 | `オブジェクト名['キー']`。キーは文字列なのでクォート必須 |
| 配列との違い | 配列は**インデックス**、オブジェクトは**キー** |
| ドット記法の弱点 | キーに定数・変数を使えない（`strawberry.key` は `undefined`） |

**学んだ主な構文**

```js
// ===== 5-9 2つの記法（p.181） =====
console.log(strawberry.name);      // ドット記法      → イチゴ
console.log(strawberry['img']);    // ブラケット記法  → strawberry.jpg
```

```js
// ===== 5-9 キーを定数で指定する場合（p.182） =====
const key = 'name';
console.log(strawberry.key);     // ドット記法      → undefined（取得できない）
console.log(strawberry[key]);    // ブラケット記法  → イチゴ（こちらのみ取得できる）
```

**できるようになったこと**：ドット記法を既定とし、**キーを定数・変数で動的に指定したいときだけブラケット記法** という判断基準を持てました。`strawberry.key` が `undefined` になる理由も説明できます。

**つまずき・気づき**
- **`strawberry.key` の挙動を実機で検証**。Node.js で `s.key` → `undefined`、`s[key]` → `イチゴ` と教材どおり。理由は **ドット記法の後ろは「文字そのもの」として扱われる**ため、定数の中身ではなく **`key` という名前のキー** を探しに行くから。※検証と言語化は自分で実施。
- **`undefined` がこれで2回目**（5-4の存在しないインデックスに続く）。**「無い場所を指した結果」は配列でもオブジェクトでも `undefined`** で共通、**エラーにならず静かに返る**のが怖いところ。
- **クォートの有無のルールが章を通して一貫**。`insertAdjacentHTML('beforeend', content)`（5-2）と同じで、**文字列そのものならクォートあり／箱の呼び出しならクォートなし**。
- **配列の `lists[0]` とオブジェクトの `strawberry['name']` が似ているのは偶然ではない**。どちらも `[ ]` の中をキーとして解釈しており、配列は数字がキーになっているだけ。※自分の理解。

### 5-10｜配列とオブジェクトを組み合わせてデータをひとまとめにしよう

**何をしたか**
- **5-10（p.185〜189／サンプル `chapter5/10-demo`）**：**6つすべてのジュースのオブジェクトを作成**し、**配列とオブジェクトを組み合わせてデータをひとまとめに**します。
- **配列にオブジェクトを入れる（p.185）**：**複数のオブジェクトをひとまとめにするには配列を使います**。**仕切りのついた箱の中に、さらに仕切りのついた箱が入るイメージ**。**そうすることで各オブジェクトにインデックスがつき、for文を使った一覧表示なども容易にできる**ようになります。
- **書き換え（p.186〜187）**：**元の要素は文字列なのでクォートで囲んでいたが、オブジェクトなので要素部分を `{}` で囲む**。インデックス0〜5に `name` / `img` / `price` を割り当てる表を提示してから書き換え、**前節の `strawberry` オブジェクトと `console.log()` はもう必要ないので削除**します。
- **値を取得する（p.188）**：おさらいとして **オブジェクトは `オブジェクト名.キー`、配列は `配列[インデックス]`**。**現在配列の中にはオブジェクトが要素として入っているため、`配列[インデックス]` で各オブジェクトにアクセスでき、値の取得は `配列[インデックス].キー` となります**。
- **検証と不具合（p.189）**：`console.log(lists[0].name);` → **「イチゴ」と表示され、うまく取得できています**。**しかし `net::ERR_FILE_NOT_FOUND` も一緒に表示され、Webページ上の画像が非表示に**。**for文で指定している `lists[i]` は各オブジェクトそのものを指定したままでキーの指定がされていないため、画像のファイル名が取得できていない**からです。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| 配列にオブジェクトを入れる | **仕切りのついた箱の中に、さらに仕切りのついた箱**が入る構造 |
| 入れ子にする利点 | 各オブジェクトに**インデックスがつく**ので一覧表示が容易 |
| `配列[インデックス].キー` | 配列の中にあるオブジェクトの値を取得する書き方 |
| `net::ERR_FILE_NOT_FOUND` | 指定したファイルが見つからないときのブラウザーのエラー |

**学んだ主な構文**

```js
// ===== 5-10 配列にオブジェクトを入れた形（p.187／js/script.js） =====
const lists = [
    {
      name: 'イチゴ',
      img: 'strawberry.jpg',
      price: 450,
    },
    // （・・・ライム400／マンゴー500／レモン400／イチジク500／リンゴ400 省略・・・）
];
// ↑ 波カッコの中には「キー」と「値」がセットになったプロパティが入る

console.log(lists[0].name);   // → イチゴ（ただし for 文は ${lists[i]} のままなので画像は出ない）
```

**できるようになったこと**：配列とオブジェクトを **入れ子** にしてデータを一元管理する形を書けるように。「箱の中に箱」を `配列[インデックス].キー` という **2段階のアクセス** として説明できるようになりました。

**つまずき・気づき**
- **`${lists[i]}` のままだと `images/[object Object]` を読みに行く**。Node.js で確認するとテンプレート文字列にオブジェクトを埋め込んだ結果は `[object Object]` で、URLエンコードすると `%5Bobject%20Object%5D`。教材 p.189 のエラー画面の表示と一致し、**「なぜファイルが見つからないのか」を具体的に説明できる**ようになった。※検証と対応づけは自分で実施。
- **`[object Object]` は「オブジェクトのまま文字列に混ぜた」ときの定番の失敗表示**。今後この文字列を見たら即座に疑える。※自分の整理。
- **`net::ERR_FILE_NOT_FOUND` はJavaScriptのエラーではない**。ブラウザーがリソース取得に失敗した通知なのでスクリプトは止まらない。**エラーの出どころで種類を見分ける**視点。※自分の補足。
- **教材があえて壊れた状態を経由させている**。「値は取れるが画像は消える」中途状態を作り、5-11で直す。**動かない理由を自分の言葉で説明できて初めて次に進む**構成。

### 5-11｜一覧表示をしよう（lists[i].img / .name / .price）

**何をしたか**
- **5-11（p.190〜193／サンプル `chapter5/11-demo`）**：**1つひとつの情報の取得方法がわかったので、あとはfor文の中に記述して一覧表示させます**。
- **画像を一覧表示させる（p.190〜191）**：**`lists[i]` に `.` でつないでキーを記述**。**画像ファイル名を格納しているキーは `img` なので `lists[i].img`**。**確認用の `console.log(lists[0].name);` はコメントアウト、または削除**。→ **各オブジェクトの画像のファイル名が取得でき、Webページ上に再び画像が表示されました**。
- **メニュー名と値段を表示する（p.191〜193）**：**定数 `content` の中、画像の指定の後にHTMLを追加**（**メニュー名は `<h2>`、値段は `<p>`**）。まず **`メニュー名` `000円` というダミーのHTMLで構造だけ確認**し、**for文で繰り返し処理が行われ、すべての画像の下に見出しと値段の要素が追加されました**。**あとは `lists[i]` にキーをつなげてメニュー名（`name`）と値段（`price`）を取得** → **これですべての情報が一覧表示されました**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| `lists[i].img` / `.name` / `.price` | i番目のオブジェクトの画像／メニュー名／値段 |
| ダミーで先に組む | 値を入れる前に固定文字でHTML構造だけ確認する進め方 |
| `<h2>` / `<p>` | メニュー名の見出し／値段の段落（5-1のCSSと対応） |

**学んだ主な構文**

```js
// ===== 5-11 完成形（p.193／js/script.js） =====
//console.log(lists[0].name);      // ← コメントアウト、または削除

for(let i = 0; i < lists.length; i++){
    const content = `<div><img src="images/${lists[i].img}" alt=""><h2>${lists[i].name}</h2><p>${lists[i].price}円</p></div>`;
    //                                        ↑画像            ↑メニュー名        ↑値段
    menu.insertAdjacentHTML('beforeend', content);
}
```

**できるようになったこと**：`lists[i].img` / `.name` / `.price` を使い分け、**1つのループから3種類の情報を同時に取り出してHTMLに組み込む** 実装。「まずダミーで構造を作り、次に値を差し込む」2段階の進め方も身につきました。

**つまずき・気づき**
- **ダミーのHTMLを先に入れる進め方が実務的**。「HTMLの構造の問題」と「値の取得の問題」を **切り分けられる**。
- **1つのループで3つの値を取り出せるのは、配列の要素がオブジェクトだから**。文字列の配列のままなら3本の配列を並走させることになり、**インデックスのずれという事故が起きやすい**。5-10の入れ子化の価値がここで効く。
- **テンプレート文字列が1行でかなり長くなった**（紙面でも折り返されている）。この体感が次節の分割代入の動機になる。**不便→解決の型が章内で4回目**。
- **`${lists[i].price}円` のように単位を後付けできる**のは、5-8のPOINTで値段を数値にしておいたおかげ。**データは数値のまま／表示のときだけ「円」を足す**という理想的な形。
- **`alt=""` のまま**なのは気になる。意味のある画像なら `alt="${lists[i].name}"` とする手も（教材は装飾画像として空にしている）。※アクセシビリティの補足は自分の考察。

### 5-12｜分割代入でコードをスッキリさせよう

**何をしたか**
- **5-12（p.194〜197／サンプル `chapter5/12-demo`）**：**前節で一旦Webページは完成しましたが、少し書き方が冗長だったところもあります**。
- **取得する値を定数にする（p.194〜195）**：**何度も `lists[i]` と記述しているため、定数 `content` のテンプレート文字列がやけに長く見えます**。**まずは取得する値をそれぞれ定数にし、定数名とキーを同じ名前にするとわかりやすい**。→ **`${img}`・`${name}`・`${price}` で呼び出せるので、テンプレート文字列がスッキリした**。
- **分割代入を使う（p.195〜196）**：**オブジェクトのキーと同じ定数名を使う場合はさらに省略でき、分割代入といって一度に複数のプロパティの値を定数に代入できます**。**書き方は `const` から始まり、`{}` の中にオブジェクトのキーを書き、複数ある場合は `,` で区切り、`=` のあとに値を取得したいオブジェクトの名前を指定**。**キーを指定するだけで同じ名前の定数に値が代入されます**。**波カッコの中のキーは順不同**で、**存在しないキーを書くと `undefined`**。
- **結果（p.197）**：**分割代入を使う前と同じように、Webページ上に画像やメニュー名、値段が表示されます**。**同じ結果となるコードであっても、より簡潔に記述する方法もあるので覚えておくといいでしょう**。

**学んだ用語**

| 用語 | やさしい説明 |
|---|---|
| 分割代入 | **一度に複数のプロパティの値を定数に代入**できる書き方 |
| 書き方 | `const { キー1, キー2, キー3 } = オブジェクト名;` |
| 定数名＝キー名 | 同じ名前になるので `${name}` のようにそのまま呼び出せる |
| キーは順不同／存在しないキー | 書く順番は自由／`undefined` になる（エラーではない） |

**学んだ主な構文**

```js
// ===== 5-12 STEP1：まず定数にする（p.195） =====
for(let i = 0; i < lists.length; i++){
    const name = lists[i].name;      // ← 定数を宣言
    const img = lists[i].img;
    const price = lists[i].price;
    const content = `<div><img src="images/${img}" alt=""><h2>${name}</h2><p>${price}円</p></div>`;
    menu.insertAdjacentHTML('beforeend', content);
}
```

```js
// ===== 5-12 STEP2：分割代入で1行に（p.195〜196／完成形） =====
const { キー1, キー2, キー3 } = オブジェクト名;   // 記述例（キーは順不同・無いキーは undefined）

for(let i = 0; i < lists.length; i++){
    const {name, img, price} = lists[i];         // ← 3行が1行に
    const content = `<div><img src="images/${img}" alt=""><h2>${name}</h2><p>${price}円</p></div>`;
    menu.insertAdjacentHTML('beforeend', content);
}
// → 見た目は変わらないまま、コードだけ簡潔になった
```

**できるようになったこと**：`lists[i].〜` の繰り返しという冗長さに気づき、**①いったん定数に置く → ②キー名と定数名が同じなら分割代入にまとめる** という2段階のリファクタリングを実行。これで **5-1の冒頭で先出しされた完成コードと同じ形** に到達します。

**つまずき・気づき**
- **分割代入の2つのルールを実機で検証**。Node.js で **定義順と違う順番＋存在しないキー** を混ぜても、正しいキーは取得でき、無いキーは `undefined`。教材どおり。※検証は自分で実施。
- **`undefined` がこれで3回目**（存在しないインデックス／ドット記法＋変数キー／無いキーの分割代入）。**無い場所を指してもエラーにならず `undefined` が返る**のがJSの一貫した性質で、裏を返せば **タイポしても止まってくれない**。
- **`const {name, img, price}` の波カッコはオブジェクトではない**。`=` の**左側**なので「取り出すキーの指定」。5-8で整理した「`=` のどちら側か」の見分け方がここでも効く。生成される定数も普通の `const` で、再代入すると `TypeError`（検証済み）。
- **「①定数に置く → ②分割代入」の2段階で見せる教え方が効いている**。3行を書いた後だと1行版が **「その省略形」** として自然に読める。
- **5-1で「今は読めなくてよい」と言われた完成コードが、12節かけて全部読めるようになった**。**章の入口と出口が同じコードで閉じている**構成の気持ちよさがある。
